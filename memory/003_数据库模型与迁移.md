# 003_数据库模型与迁移

## 当前方案

系统使用 SQLAlchemy 2.x 和 SQLite。数据库默认位于 `data/value_investment.db`，连接创建逻辑会把相对 SQLite 路径解析到后端目录，并启用 `check_same_thread=False`。

每个 SQLite 连接同时执行 `PRAGMA foreign_keys=ON`，数据清理按 `PriceDecisionRun -> ValuationRun -> InvestmentMemo -> AnalysisRun` 的依赖方向删除，避免留下悬空外键。

启动时 `init_db()` 依次执行：

1. `Base.metadata.create_all()` 创建缺失表。
2. `run_schema_migrations()` 对旧 SQLite 增补列、索引和兼容数据。
3. `seed_db()` 幂等写入真实公司种子。

当前 schema version 为 `9`。v4 将历史 `price_decision_runs.analyst_score_total` 改为可空，停止为已经退出合同的 009 评分伪造 `0`；v5 增加发行人字段、`SecurityListing`、不可变 `MarketSnapshot`、`FxRateSnapshot`，并为财务、公告、010 和 011 增加市场审计字段；v6 为 `FxRateSnapshot` 增加可空 `calculation_audit`；v7 增加 015 的四张首版表；v8 为持仓人与持仓快照增加持久化 `display_order`；v9 增加 `BuyMemoEntry`，以快照字段保存选定 011 结果并用 `ON DELETE SET NULL` 的可空来源外键保持来源追溯。迁移为每个旧 Company 回填一个主 Listing，保留原 `company_id` 及全部研究关系；有效旧行情仅以 `legacy_company_snapshot` 来源生成可追溯快照，缺失行情不伪造快照或 0 值，旧 FX 快照的审计字段保持 `NULL`。

公司种子池当前包含 75 家公司，其中 A 股 48 家、港股 5 家、美股 22 家；标准新库包含 78 个 Listing（阿里 `BABA.US`、伯克希尔 `BRK.A.US` 与 Alphabet `GOOG.US` 为各自发行人的次级 Listing）。本轮新增美国运通、美国银行、雪佛龙、安达保险、穆迪、卡夫亨氏、达美航空、天狼星 XM、Credo，并补齐 GOOG/GOOGL 双股类；此前新增 PDD、CRCL、09992.HK 和 OXY。PDD 明确为 ADS 且 `1 ADS = 4 ordinary shares`，组合估值仍只按 ADS 数量乘 ADS 市价。启动初始化不覆盖公司研究状态；对于已经由真实 Provider 丰富的 `legal_name/aliases/domicile_country/reporting_currency/fiscal_year_end/external_ids`，种子只补空值并合并缺失外部 ID，不把来源事实回写成旧种子默认值。Apple 和 Alibaba 新库默认财年结分别为 `09-26`、`03-31`。

2026-08-22 真实项目库已幂等迁移为 schema v9，`integrity_check=ok`；最终验收时为 99 家公司/102 个 Listing，相对标准 75/78 的 24 家差额均为用户通过 SEC 目录导入的公司，迁移和日常初始化均予以保留。015 的 4 个持仓人、4 张快照和当前 60 条持仓未被本轮迁移或验收改写；`buy_memo_entries` 已由用户录入 3 条。

当前未使用 Alembic。

## 核心实体

| 实体 | 主要用途 | 关键关系 |
| --- | --- | --- |
| `Company` | 发行人身份、档案及主 Listing 兼容镜像 | 所有研究对象的根实体，历史 `company_id` 不迁移 |
| `SecurityListing` | 上市证券身份、市场、交易币种、证券单位换算 | `company_id`，同公司最多一个启用主 Listing |
| `MarketSnapshot` | Listing 级不可变行情与估值倍数快照 | `listing_id`，011 新运行必须绑定 |
| `FxRateSnapshot` | 币种方向、日期、来源和汇率快照 | 011 跨币种新运行绑定 |
| `PortfolioOwner` | 015 持仓人身份 | 存在快照时 API 拒绝删除；`display_order` 保存用户排序 |
| `PortfolioSnapshot` | 某持仓人的历史披露/统计日期组合 | 删除时显式级联自身持仓，不覆盖旧日期；按持仓人保存 `display_order` |
| `PortfolioHolding` | 快照内具体 Listing 的证券数量 | `snapshot_id + listing_id` 唯一，quantity 为 `NUMERIC(28,8)` |
| `MarketFearSnapshot` | A/H/美市场温度最近成功缓存 | 按市场、数据日期和来源去重，失败时保留旧成功记录 |
| `BuyMemoEntry` | 015 买入备忘录中的冻结 011 摘要 | 同一来源 011 只能导入一次；来源删除时外键置空，内在价值、买入价、安全边际、报告期和版本快照保留 |
| `FinancialStatement` | 主指标、利润表、现金流量表、资产负债表及期间/来源审计 | `company_id` |
| `Announcement` | 公告元数据、正文、最新摘要及 Listing/文档溯源 | `company_id`、可空 `listing_id` |
| `Evidence` | 外部证据、评分、复核与原始快照 | `company_id` |
| `AnalysisRun` | 搜索、分析师和 Memo 生成运行记录 | `company_id`、可选父运行 |
| `InvestmentMemo` | 投资备忘录版本及来源分析 | `company_id`、`generation_run_id` |
| `ValuationRun` | price-blind 估值草稿、估值币种和 share basis | `company_id`、可选 `memo_id` |
| `PriceDecisionRun` | Listing 行情、可选 FX 与冻结 010 的价格对照版本 | `company_id`、`valuation_run_id`、`memo_id`、新记录的 Listing/MarketSnapshot |
| `ParameterConfigVersion` | 旧版参数配置记录（兼容保留） | 新配置流程不再读取或写入此表，不创建草稿、版本、历史或回滚记录 |

## 数据约束

- Company 使用稳定且可空兼容的 `canonical_key` 识别发行人；旧 `ticker/exchange/listed_date` 和行情字段是主 Listing 兼容镜像。
- Listing 以 `exchange + ticker` 唯一识别；同一 Company 最多一个 `is_primary=true` 且启用的 Listing。
- 种子按 `canonical_key` 合并同一发行人并追加 Listing，不再用同名证券原地覆盖另一个市场身份；主 Listing 切换原子更新 Company 兼容镜像。
- `MarketSnapshot` 每次刷新只新增记录；历史价格决策继续读取自身冻结值，新字段对历史可空且不回算。
- 财务和公告同步按来源标识去重并更新，不覆盖需要保留的人工/模型结果。
- 分析运行通过 `run_type`、`analyst_profile`、`status` 和 `is_latest` 管理当前结果与历史。
- Memo 使用 `version_no`、`parent_memo_id` 和 `is_latest` 管理版本。
- 估值重算创建新记录并保留来源运行，不原地覆盖。
- 价格决策使用 `version_no` 和 `deleted_at`；列表默认排除已软删除记录。
- JSON 字段保存输入快照、结构化输出、来源图、方法结果和诊断，便于重放与审计。
- `ParameterConfigVersion` 表为兼容旧数据库保留，但当前初始化、读取和发布流程均不再使用它；未发布编辑不会写入数据库。
- `AnalysisRun`、`InvestmentMemo`、`ValuationRun`、`PriceDecisionRun` 保留可空 `config_version/config_hash` 与非空 `config_snapshot`。新运行的 `config_version` 为 `null`，哈希和完整快照仍确保历史结果可复现。
- 持仓人与同一持仓人的快照列表按 `display_order, id` 读取；重排 API 必须完整且无重复地提交当前 ID 集合。v8 首次回填时，持仓人保持原 ID 顺序，快照保持原日期倒序及同日新建优先顺序；迁移重复执行不会覆盖用户后续排序。

## 迁移边界

当前迁移器适合单机 SQLite 的向前兼容：新增表、列、索引和少量数据规范化。涉及删列、复杂回填、跨数据库或生产回滚时，应引入 Alembic 并停止继续扩展手写迁移。

2026-08-22 当前 SQLite schema version 为 9。v7 通过 `Base.metadata.create_all()` 幂等创建 015 四张首版表；v8 对已有 015 表增补并回填两个排序字段；v9 由模型和显式 `CREATE TABLE IF NOT EXISTS` 双路径幂等创建买入备忘录表及索引。独立迁移 fixture 已验证初始顺序、用户重排、v9 新表及重复迁移幂等；v4-v6 的列补齐、索引顺序、Company ID、旧行情/FX 及 004-011 历史兼容逻辑保持不变。

2026-08-22 A/H/美股动态证券目录、TME 和 BRK 修复没有新增表、列、索引或迁移版本；外部候选只有在用户选择后才写入既有 `Company/SecurityListing`。真实库继续为 schema v9、`integrity_check=ok`，TME 的 ADS Listing 单位比例保持 `NULL`，不会为历史估值伪造换股关系。

## 数据维护边界

- 备份使用 SQLite Backup API，不直接复制正在写入的数据库文件。
- 初始化在维护锁内先创建备份，再重建结构、执行当前迁移并写入 75 家标准公司种子；失败时从刚创建的备份恢复。
- 恢复前先备份当前数据库，恢复失败时回滚到该恢复前备份。
- 物理清理只删除安全的软删除记录；`archived` Memo 和仍被估值、价格决策或 Memo 版本链引用的记录保留。
- `VACUUM` 在提交删除事务后用 AUTOCOMMIT 连接执行，并在执行前检查磁盘空间。
