# 003_数据库模型与迁移

## 本轮时间

2026-08-09 02:56 +08:00

## 本轮目标

把后端从纯健康检查推进到可承载公司研究数据的最小数据库层，补上 SQLite、SQLAlchemy、基础表、种子数据和公司列表 API 的骨架。

## 已完成

1. 建立 SQLite 数据库连接。
2. 引入 SQLAlchemy 2.x ORM。
3. 创建基础表：
   - `companies`
   - `financial_statements`
   - `announcements`
   - `analysis_runs`
4. 增加最小种子数据：
   - 3 家示例公司
   - 1 条财务报表示例
   - 1 条公告示例
   - 1 条分析运行示例
5. 新增公司列表 API：
   - `GET /api/companies`
   - 支持 `q`、`limit`、`offset`

## 新思考

- 这一轮先不引入 Alembic。当前目标是把本地研究工作台跑起来，`Base.metadata.create_all()` 足够支撑第一个可用闭环。
- 种子数据刻意使用示例公司名，而不是抓取真实实时数据，避免把不稳定外部事实写死在初始化层。
- 公司列表接口返回 `total + items + offset + limit`，这样后续公司搜索页能直接做分页，不需要再改响应结构。
- SQLite 路径按后端目录解析，环境变量即使写相对路径，也不会因为启动目录不同而失效。

### 新思考

- 暂时仍不引入 Alembic。这个项目目前是本地优先研究工作台，SQLite + `create_all()` + 轻量补列迁移更贴合当前阶段。
- 迁移逻辑从 `init_db.py` 拆出去后，后续再新增字段时可以集中扩展 `SQLITE_COLUMN_MIGRATIONS`，避免初始化入口继续膨胀。
- `PRAGMA user_version` 先作为本地 schema 基线标记，不做复杂版本脚本链；等 schema 变更需要数据回填或破坏性迁移时，再考虑 Alembic 或版本化迁移函数。
