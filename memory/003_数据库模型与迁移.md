# 003_数据库模型与迁移

## 当前方案

系统使用 SQLAlchemy 2.x 和 SQLite。数据库默认位于 `data/value_investment.db`，连接创建逻辑会把相对 SQLite 路径解析到后端目录，并启用 `check_same_thread=False`。

每个 SQLite 连接同时执行 `PRAGMA foreign_keys=ON`，数据清理按 `PriceDecisionRun -> ValuationRun -> InvestmentMemo -> AnalysisRun` 的依赖方向删除，避免留下悬空外键。

启动时 `init_db()` 依次执行：

1. `Base.metadata.create_all()` 创建缺失表。
2. `run_schema_migrations()` 对旧 SQLite 增补列、索引和兼容数据。
3. `seed_db()` 幂等写入真实公司种子。

当前 schema version 为 `3`。`seed_db()` 只维护业务种子，不再创建参数配置记录；当前参数来自固定源码文件 `backend/app/configuration/active_parameters.json`，文件不存在时使用集中内置默认配置。

公司种子池当前包含 62 家公司，其中 A 股 48 家、港股 4 家、美股 10 家。启动初始化只补充或更新主数据，不覆盖公司研究状态。

当前未使用 Alembic。

## 核心实体

| 实体 | 主要用途 | 关键关系 |
| --- | --- | --- |
| `Company` | 证券身份、档案、行情与市值快照 | 所有研究对象的根实体 |
| `FinancialStatement` | 主指标、利润表、现金流量表、资产负债表 | `company_id` |
| `Announcement` | 公告元数据、正文与最新摘要 | `company_id` |
| `Evidence` | 外部证据、评分、复核与原始快照 | `company_id` |
| `AnalysisRun` | 搜索、分析师和 Memo 生成运行记录 | `company_id`、可选父运行 |
| `InvestmentMemo` | 投资备忘录版本及来源分析 | `company_id`、`generation_run_id` |
| `ValuationRun` | price-blind 估值草稿和计算结果 | `company_id`、可选 `memo_id` |
| `PriceDecisionRun` | 估值与价格对照后的决策版本 | `company_id`、`valuation_run_id`、`memo_id` |
| `ParameterConfigVersion` | 旧版参数配置记录（兼容保留） | 新配置流程不再读取或写入此表，不创建草稿、版本、历史或回滚记录 |

## 数据约束

- 公司以 `ticker + exchange` 唯一识别。
- 同一公司存在多地上市证券时，默认市场优先级为 A 股 > 港股 > 美股。
- 种子发现同名的低优先级市场记录时，会原地升级证券身份并保留 `company_id` 及其研究关系；旧市场的上市日期和行情快照会清空，避免跨市场数据混用。
- 财务和公告同步按来源标识去重并更新，不覆盖需要保留的人工/模型结果。
- 分析运行通过 `run_type`、`analyst_profile`、`status` 和 `is_latest` 管理当前结果与历史。
- Memo 使用 `version_no`、`parent_memo_id` 和 `is_latest` 管理版本。
- 估值重算创建新记录并保留来源运行，不原地覆盖。
- 价格决策使用 `version_no` 和 `deleted_at`；列表默认排除已软删除记录。
- JSON 字段保存输入快照、结构化输出、来源图、方法结果和诊断，便于重放与审计。
- `ParameterConfigVersion` 表为兼容旧数据库保留，但当前初始化、读取和发布流程均不再使用它；未发布编辑不会写入数据库。
- `AnalysisRun`、`InvestmentMemo`、`ValuationRun`、`PriceDecisionRun` 保留可空 `config_version/config_hash` 与非空 `config_snapshot`。新运行的 `config_version` 为 `null`，哈希和完整快照仍确保历史结果可复现。

## 迁移边界

当前迁移器适合单机 SQLite 的向前兼容：新增表、列、索引和少量数据规范化。涉及删列、复杂回填、跨数据库或生产回滚时，应引入 Alembic 并停止继续扩展手写迁移。

2026-08-16 当前 SQLite schema version 为 3。迁移测试从旧结构连续执行两次初始化，明确断言 `parameter_config_versions` 完整列集及 008-011 四张运行表的 `config_version/config_hash/config_snapshot` 均已创建，并校验 `PRAGMA user_version`。

## 数据维护边界

- 备份使用 SQLite Backup API，不直接复制正在写入的数据库文件。
- 初始化在维护锁内先创建备份，再重建结构、执行当前迁移并写入 62 家标准公司种子；失败时从刚创建的备份恢复。
- 恢复前先备份当前数据库，恢复失败时回滚到该恢复前备份。
- 物理清理只删除安全的软删除记录；`archived` Memo 和仍被估值、价格决策或 Memo 版本链引用的记录保留。
- `VACUUM` 在提交删除事务后用 AUTOCOMMIT 连接执行，并在执行前检查磁盘空间。
