# 008_分析师视角引擎

## 模块职责

008 把同一组公司证据交给不同投资框架独立审视，输出可引用的规则判断、风险、数据缺口和估值参数矩阵。它不输出买卖、仓位或价格结论。

## 分析师 Profile

当前有 10 个固定 Profile，每个 4 条规则，共 40 条：

- 巴菲特、彼得林奇、芒格、段永平、格雷厄姆
- 费雪、林园、李录、瑞达利欧、乔治索罗斯

Profile 在代码中定义，包含理念、规则、重点主题和 prompt focus。规则 ID 是 009 评分和 010 参数聚合的稳定合同。

## 40 个分析指标含义

### 巴菲特

1. `moat` 护城河：判断公司是否拥有可持续的竞争优势、客户黏性和定价能力。
2. `quality` 盈利质量：判断利润是否真实、稳定，并且能够转化为经营现金流。
3. `management` 管理层：判断管理层是否诚信、审慎、透明，并合理配置股东资本。
4. `margin_of_safety` 安全边际：判断当前经营风险和估值水平是否留有足够的判断容错空间。

### 彼得林奇

5. `understandable_business` 可理解业务：判断公司的赚钱方式、客户来源和增长驱动是否清楚易懂。
6. `growth_runway` 成长空间：判断收入和利润是否具有能够持续兑现的长期增长空间。
7. `story_vs_numbers` 故事与数字：判断公司的经营叙事是否得到财务数据和公告事实验证。
8. `balance_sheet_risk` 资产负债风险：判断成长背后是否隐藏负债、现金流、存货或营运资金压力。

### 芒格

9. `mental_models` 多元模型：判断公司的竞争优势能否同时通过规模、品牌、网络效应等多个基础模型解释。
10. `incentives` 激励机制：判断管理层、员工、渠道和客户的利益是否与公司长期价值一致。
11. `culture` 企业文化：判断公司是否具有理性、诚信、克制和长期主义的决策文化。
12. `avoid_stupidity` 不碰清单：检查公司是否存在欺诈、过度杠杆、复杂交易或极端尾部风险。

### 段永平

13. `business_quality` 生意模式：判断公司是否是一门简单、可持续并能够长期创造价值的好生意。
14. `benfen_culture` 本分文化：判断公司的公告和实际行为是否体现诚信、克制和不占便宜。
15. `consumer_mindshare` 消费者心智：判断产品和品牌是否在消费者心中形成稳定、难以替代的位置。
16. `shareholder_return` 股东回报：判断自由现金流、分红和回购是否体现良好的长期资本配置能力。

### 格雷厄姆

17. `asset_protection` 资产保护：判断现金、资产和负债结构能否在经营恶化时提供下行保护。
18. `earnings_stability` 盈利稳定性：判断公司盈利是否能够穿越周期，以及历史波动能否得到合理解释。
19. `conservatism` 保守假设：判断证据不足时是否应维持未知，而不是采用乐观推断补齐缺口。
20. `valuation_discipline` 估值纪律：判断现有财务和经营事实是否足以支持市场给予的较高增长预期。

### 费雪

21. `long_term_growth` 长期成长：判断公司是否具备长期扩大市场、产品和经营规模的能力。
22. `innovation` 创新能力：判断研发投入、产品升级和技术积累是否能够形成实际竞争优势。
23. `sales_execution` 销售执行：判断收入增长是否得到渠道扩张、客户增加或市场份额提升支持。
24. `management_depth` 管理深度：判断公司是否拥有能够持续投入、培养组织和执行长期战略的管理团队。

### 林园

25. `must_have_demand` 刚性需求：判断产品是否具有持续、重复且不容易消失的消费需求。
26. `brand_power` 品牌壁垒：判断品牌、渠道和用户心智是否能够阻止竞争者轻易抢走客户。
27. `cash_generation` 现金创造：判断账面利润是否能稳定转化为现金流、分红和可支配资金。
28. `compounding` 复利能力：判断公司能否持续利用利润和资本扩大未来经营成果。

### 李录

29. `circle_of_competence` 能力圈：判断当前证据是否足以真正理解公司的业务模式和关键风险。
30. `depth_of_research` 研究充分度：判断财务、公告和外部证据是否覆盖了作出结论所需的关键事实。
31. `intrinsic_value` 内在价值线索：判断长期现金流、竞争地位和资本回报是否支持持续创造价值。
32. `permanent_loss` 永久损失：判断是否存在治理失败、资产恶化或商业模式崩溃等不可逆风险。

### 瑞达利欧

33. `macro_sensitivity` 宏观敏感度：判断业务对利率、通胀、汇率、商品价格和经济增速的敏感程度。
34. `cycle_position` 周期位置：判断公司当前处于行业或经济周期的上升、顶部、下降还是修复阶段。
35. `credit_liquidity` 信用流动性：判断债务结构、现金流和融资环境是否可能造成偿债或流动性压力。
36. `portfolio_risk_signal` 组合风险信号：判断公司是否集中暴露于某个宏观变量或与其他资产相同的共同风险。

### 乔治索罗斯

37. `reflexivity` 反身性：判断市场预期、公司行为和经营结果是否正在形成相互强化或反向修正。
38. `narrative_gap` 预期偏差：判断市场或公司叙事与实际财务表现之间是否存在明显落差。
39. `macro_fragility` 宏观脆弱点：判断信用、流动性、监管、汇率或周期冲击是否会放大公司风险。
40. `counter_evidence` 反方证据：寻找最有可能推翻当前乐观或悲观判断的事实和证据。

## 输入快照

每次分析保存独立快照，来源包括：

- 公司身份和行业特征
- 最近 40 个财务报告期及财务证据包
- 已有公告摘要和官方披露事实
- 已分析或可使用的外部证据
- 来源覆盖矩阵、事实账本、会计事件和预模型观察

快照保留来源 ID、报告期和数据质量。模型不能自行联网或补造未提供事实。

007 手动文本导入成功后会形成普通 Evidence 记录，因此未删除且可使用的手动导入证据会自然进入 008 输入快照；用户在 007 删除 Evidence 后，该记录不再从 Evidence 表读取，也不会进入后续分析。

## 输出结构

主要输出包括：

- `rule_checks`：4 条规则的 `pass / warn / fail / unknown` 状态、解释与引用
- 核心判断、积极证据、反方证据、风险和待验证问题
- 数据覆盖、置信度、Profile 适配度和分析依据说明
- 会计事件与财务质量提示
- `valuation_parameter_matrix`

人工修改单条规则状态后，服务会重新派生当前运行的估值参数矩阵，避免状态与参数信号不一致。

## 估值参数矩阵

矩阵把分析结论投影到 13 个估值维度，包括增长、利润率、再投资、资本开支、营运资本、折现率、终值、资产质量和分红等参数方向。每个维度保留：

- 方向与强度
- 规则状态和证据引用
- 是否通过 gate
- 数据置信度与 Profile 适配度
- 对 010 的可用性

巴菲特的 `margin_of_safety` 和格雷厄姆的 `valuation_discipline` 属于 `price_reference` 审计项，不进入 010 参数计算。

## Price-blind gate

- 输入会清除当前价格、市值、历史价格、买卖建议和价格敏感文本。
- 规则输出不能包含交易动作或仓位建议。
- 价格参考类规则可以保留审计结果，但不会成为估值参数。
- 未知或证据不足的结论必须显式标记，不得用模型常识补齐。

## API

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| `GET` | `/api/analyst-profiles` | Profile 与规则列表 |
| `GET` | `/api/companies/{company_id}/analysis/runs/latest` | 各 Profile 最新运行 |
| `GET` | `/api/companies/{company_id}/analysis/runs` | 分析历史 |
| `POST` | `/api/companies/{company_id}/analysis/runs` | 运行单个 Profile |
| `POST` | `/api/companies/{company_id}/analysis/runs/batch` | 批量运行 Profile |
| `PATCH` | `/api/companies/{company_id}/analysis/runs/{run_id}/rule-checks/{rule_id}` | 修改规则状态 |
| `DELETE` | `/api/companies/{company_id}/analysis/runs/{run_id}` | 删除运行 |

## 前端行为

- 支持单个或全部 Profile 运行、停止等待、查看最新结果和失败原因。
- 规则状态可直接人工纠正，并立即刷新矩阵。
- 会计口径事件在视角结果底部集中展示，避免在每条规则中重复。
- 历史删除只在用户显式操作后执行。

## 当前限制

- 模型分析质量受 005-007 的数据覆盖影响。
- Profile 是规则化研究视角，不代表对人物真实观点的复刻。
- 对复杂行业和会计事项仍需人工补充证据和调整规则状态。

## 2026-08-16 财务金额与百分比模型展示口径修复

用户发现彼得林奇分析贵州茅台时，把
`operating_cash_flow_to_revenue = 0.7793628296` 错写成 `0.78%`。
005 财务证据包的标准口径没有问题：比率统一按 `0-1` 小数保存，
该值实际表示 `77.94%`。问题出在 008 直接把计算值交给模型，模型可能把原始小数直接追加百分号。

本次调整：

- 008 输入快照的 `financial_evidence_pack` 新增 `model_display`。
- `model_display.unit_contract` 明确：金额原值是 CNY 元，`1亿元=100,000,000元`；
  比率原值是 `0-1` 小数，百分比必须乘以 100。
- `model_display.latest_percentages` 为后端确定性换算后的百分比，
  同时保存 `raw_decimal`、`percent_value` 和最终 `display`。
- `model_display.latest_amounts_100m_cny` 和 `amount_series_100m_cny`
  提供后端确定性换算后的亿元展示值，避免模型把金额除以 10 亿。
- 分析师提示词升级为 `analyst_view_v2`，要求金额和百分比优先使用
  `model_display` 的 `display`，不得自行把原始值拼接单位。
- 模型结果落库前增加确定性校正：如果“经营现金流/收入”等相关文本
  仍把原始小数直接写成百分比，会自动替换为快照中的正确展示值。

贵州茅台当前快照验证：

- `operating_cash_flow_to_revenue`：原始 `0.7793628296`，展示 `77.94%`。
- 营业总收入：`922.78亿元`。
- 归母净利润：`445.17亿元`。
- 经营现金流：`706.91亿元`。
- 自由现金流：`698.59亿元`。

本次验证：

- Ruff 检查通过。
- `backend/app/tests/test_analysis.py` 通过，`35 passed`。
- 新增测试覆盖快照百分比展示值，以及模型错误返回 `0.28%` 时自动纠正为 `28.00%`。
