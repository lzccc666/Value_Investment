# 008 分析师视角引擎

## 职责与边界

008 使用同一份已入库财务、公告与外部证据，让 8 个固定投资框架独立输出结构化判断；当现有输入不足时，模型可自主调用临时 `web_search` 补充公告之外的公开基本面信息。008 不读取当前价、历史价、市值、估值倍数、评级、目标价、持仓成本、市场情绪、安全边际或交易动作，也不生成买卖建议。

输入快照会递归删除价格锚字段，并清洗嵌套文本。模型输出会再次递归检查；只要任意字段或文本包含价格锚，整次运行失败并保存失败原因，不允许把单条规则降级后继续使用。

当前提示版本为 analyst_view_v6。提示词要求优先使用快照，在行业、竞争、渠道、监管、治理或产品等公开基本面信息不足时自行搜索，不需要用户确认。Prompt 使用“只允许经营、会计、现金流、资产负债、资本配置、治理、竞争和行业内容”的正向边界，不再向模型逐项列举容易被复述到 JSON 的价格锚技术词。

模型第一次结构化输出命中价格锚时，服务会丢弃该输出，以温度 0 和更严格的基本面边界从头自动生成一次；第二次仍命中才将本次运行标记为失败。自动重生成不接受、不清洗也不局部保留第一次越界结果，后端硬门禁始终不变。

价格盲区门禁按语义区分基本面表述与投资者决策表述：`safety_margin` 技术字段及估值语境的“安全边际”继续禁止，但“财务安全边际”“偿债安全边际”“流动性安全边际”等资产负债表描述允许；明确的买卖或仓位建议继续禁止，但“公司持有证券”“卖出产品”等公司经营或资产持有事实允许。这样不会因裸关键词“持有”或“安全边际”误杀合法基本面结论。

## 深度档案

每个 Profile 同时公开并注入提示词：

- description：该框架观察公司的入口。
- philosophy：框架的核心投资哲学。
- core_logic：关键推理原则。
- decision_sequence：固定分析顺序。
- preferred_evidence：优先采用的证据类型。
- failure_modes：常见误判方式。
- prompt_focus：模型必须重点回答的主题。
- rules：四条规则的标签、完整说明和五状态判定口径。

每条规则的 status_rubric 都包含 pass、neutral、unknown、warn、fail。unknown 的统一含义是关键证据缺失、来源冲突或口径不可比；neutral 表示证据足以判断但结论普通或无明显正负倾向。

## 运行输出

规则状态及分值合同：

| 状态 | 分值 | 含义 |
| --- | ---: | --- |
| pass | 1.0 | 明确满足 |
| neutral | 0.0 | 可判断但中性 |
| unknown | -0.1 | 证据不足 |
| warn | -0.5 | 存在重要警示 |
| fail | -2.0 | 明确不满足 |

每次成功运行保存：

- overview、key_observations、financial_observations、announcement_observations。
- 精确 4 条 rule_checks，顺序必须与 Profile 定义一致。
- risk_flags、counter_evidence、data_gaps、follow_up_questions。
- valuation_assumption_suggestions 与可追溯 source_refs。
- profile_fit_score、confidence、配置版本与完整配置快照。
- valuation_parameter_matrix：4 条规则全部 calculation_role=compute，全部 price_blind_compatible=true。

旧 parameter_impacts 和 price_reference 层已退出运行时合同。32 条规则全部参与 010 数值聚合。

008 的结构化规则结果是 010 的分析师影响事实源：每条规则的 `status`、状态分值、规则到维度的映射贡献，以及 Profile 的 `data_confidence`、`profile_fit_score` 和分析师权重都会保留在 010 的输入快照。010 根据这些结果分别形成质量、成长、风险、情景宽度和动态安全边际影响；009 的 Memo 只总结这些判断，不替代 008 结果参与数值计算。

## 数据与证据

分析快照保存以下已入库数据：

- 公司静态档案中允许的非价格字段。
- 财务证据包、财务期间与确定性指标。
- 公告摘要及公告 ID。
- 外部 Evidence 及 Evidence ID。
- 数据缺口、来源哈希与配置快照。

规则引用只能指向快照中真实存在的 evidence_ids、announcement_ids 和 financial_periods。

### 临时联网搜索

- 008 调用 DeepSeek Chat Completions 时始终提供一个自定义 `web_search` function，模型自行决定是否调用，不增加分析模式或前端开关。
- 搜索执行器直接复用底层 DuckDuckGo/Bing HTML 搜索提供器，不经过 007 的查询规划、证据结构化和入库流程。
- 每次工具调用默认返回最多 5 条搜索结果，单次模型生成最多允许 3 轮搜索；达到上限后强制模型基于已有上下文输出最终 JSON。
- 不设置站点白名单，默认搜索全网；工具说明要求只补充公开基本面信息，不搜索行情、目标价、评级和交易建议。
- 搜索结果仅作为当前模型对话的临时上下文，不写入 Evidence，不进入分析快照，也不要求最终结果展示网址。
- 相同规范化查询在当前后端进程内缓存 15 分钟，最多保留 128 个查询；这是搜索结果缓存，服务重启后失效。
- DeepSeek API 另外默认提供输入前缀上下文缓存。它可能降低多轮工具调用和重复快照的 Token 成本，但属于 best-effort，不保证命中，也不等同于搜索结果缓存。
- 搜索失败会以工具错误结果返回模型，模型应继续使用财务、公告和既有外部证据完成分析，不因临时搜索不可用直接丢失原有能力。
- 联网内容没有 Evidence ID，模型不得为其伪造 `evidence_ids`、`announcement_ids` 或 `financial_periods`。

## API 与前端

- GET /api/analysis/profiles：按固定顺序返回 8 个深度档案和规则 rubric。
- POST /api/companies/{company_id}/analysis/runs：运行单个 Profile。
- POST /api/companies/{company_id}/analysis/runs/batch：运行指定 Profile；空列表表示全部 8 个。
- PATCH /api/analysis/runs/{run_id}/rule-checks/{rule_id}：人工修改五状态之一，并重建该运行的规则矩阵。
- GET /api/companies/{company_id}/analysis/runs/latest：无状态筛选时读取各 Profile 最新运行；`status=success` 时读取各 Profile 最近一次成功运行，使新的运行中或失败尝试不会遮住 008 页面已有评价；`status=failed` 仍只返回当前最新记录确为失败的 Profile。

前端按固定顺序展示 8 个分析师，并展示每人最近一次成功评价、哲学、核心逻辑、决策顺序、偏好证据、失败模式、规则说明及五状态 rubric。重新生成期间保留原成功评价。“生成缺失”只向批量接口提交尚无成功 run 的 Profile；8 人均已有成功 run 时按钮禁用且不发送空列表，避免触发后端“空列表表示全部”的语义。

## 结构性约束

- Profile 必须恰好 8 个，每人恰好 4 条规则，总计 32 条。
- 规则矩阵必须恰好 32 条、13 个维度、117 个维度系数，全部 compute。
- 输入和输出都必须保持价格盲区。
- 价格锚输出不能进入成功结果；首次命中只允许整份丢弃后自动重生成一次，第二次命中必须使整次 008 失败，不能降级、字符串替换、局部忽略或伪造旧结果。
- 手工修改只影响目标历史运行；已保存的 009、010、011 快照不原地重算。修改后要让 010 读取新的最新成功 008 矩阵，才会影响新的估值草稿。

## 014 多市场输入展示（2026-08-21）

- 财务模型输入新增通用 `latest_amounts_100m` 与 `amount_series_100m`，金额按证据包真实 `reporting_currency` 展示，例如 `4100.00亿 USD`；原 CNY 别名仅为 A 股历史兼容，不再作为跨市场计算事实源。
- 公司、财务和公告快照增加发行人、Listing、期间、会计准则、披露语言/表单等非价格审计上下文。所有新增字段仍经过递归价格盲区门禁，008 的 8 人、32 规则、五状态、13 维度和 117 系数不变。
- 前端进入 Analyst Views 时继续完整显示公共公司档案和行情信息，保证研究对象上下文与其他工作区一致。该展示层信息不进入 008 请求快照；008 后端仍递归清除价格锚，并对模型输入和输出执行原有硬门禁。
