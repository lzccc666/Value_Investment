# 002_项目脚手架与开发环境

## 环境基线

- Windows PowerShell
- Python 3.11+
- Node.js 与 npm
- 后端虚拟环境：`backend/.venv`
- 前端依赖目录：`frontend/node_modules`
- 本地数据库：`data/value_investment.db`

## 项目结构

```text
backend/app/
  api/routes/       FastAPI 路由
  analysis/         模型网关、Profile 与提示词
  core/             配置
  data_sources/     外部数据适配器
  db/               模型、初始化、迁移
  schemas/          Pydantic 合约
  services/         领域逻辑
  tests/            后端测试
frontend/src/
  app/               页面与工作区
  components/        通用组件
  services/          API 客户端
  styles/            全局样式
  tests/             前端测试
```

## 初始化与启动

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\setup_windows.ps1
powershell -ExecutionPolicy Bypass -File .\scripts\dev_windows.ps1
```

启动脚本支持只启动前端、只启动后端、强制重启和自定义端口。使用以下命令查看当前参数：

```powershell
Get-Help .\scripts\dev_windows.ps1 -Detailed
```

默认前端为 `127.0.0.1:5173`。Vite 通过 `VITE_BACKEND_PORT` 把 `/api` 代理到后端；Vite 配置的独立默认后端端口为 `8001`，启动脚本默认后端端口为 `8000`，因此手动启动时必须让两者一致。

## 前端当前结构

- Dashboard：公司总数、当前研究对象、8/8 主链路和最近公司。
- Company Search：搜索、分页、选择和新增公司。
- Company Workspace：Overview、Financials、Announcements、Evidence、Analyst Views、Memo、Valuation Lab、Price Decision。
- 侧边栏入口和 Dashboard 主链路均映射到同一组工作区 section。
- 当前研究对象保存在前端会话状态中；对象失效时返回搜索页。

## 配置

后端设置来自 `backend/.env`，使用 Pydantic Settings。默认数据库 URL 指向项目根目录 SQLite；默认 CORS 允许本机 `5173`。

模型相关变量：

```dotenv
MODEL_BASE_URL=
MODEL_API_KEY=
MODEL_NAME=
MODEL_WIRE_API=chat_completions
MODEL_REASONING_EFFORT=
MODEL_DISABLE_RESPONSE_STORAGE=false
MODEL_TIMEOUT_SECONDS=180
```

## 验证流程

```powershell
Set-Location backend
.\.venv\Scripts\python.exe -m ruff check app
.\.venv\Scripts\python.exe -m pytest

Set-Location ..\frontend
npm test
npm run build
```

运行态验证至少检查：

1. `/api/health` 返回服务名和版本。
2. Dashboard 能读取公司池并进入 8 个研究模块。
3. 前端通过 `/api` 代理访问后端，没有 CORS 或端口错配。
4. 桌面与移动宽度下无文字覆盖、横向溢出或不可操作控件。

## 当前限制

- 开发脚本面向 Windows 本地环境，不是生产部署方案。
- 长耗时模型调用在 HTTP 请求内执行，尚无后台任务队列。
- SQLite 和单进程服务适用于个人研究，不适合多用户并发。
- 日志以开发期控制台和脚本日志为主，尚未统一结构化追踪。
