## 2026-08-14 22:31 +08:00 API 连接修复

用户反馈前端显示：

```text
加载失败
NetworkError when attempting to fetch resource.
API未连接
```

排查结果：

- 后端直连 `GET http://127.0.0.1:8001/api/health` 正常返回 `status=ok`。
- 前端代理 `GET http://127.0.0.1:5174/api/health` 也能正常返回 `status=ok`。
- 问题原因是 `scripts/dev.ps1` 在启动前端时设置了 `VITE_API_BASE_URL=http://127.0.0.1:8001/api`，导致浏览器从 `5174` 页面跨端口直连 `8001`。后端默认 CORS 只放行 `5173`，在备用端口 `5174` 下会触发浏览器侧 `NetworkError`。

已修复：

- 修改 `scripts/dev.ps1`，将开发环境中的 `VITE_API_BASE_URL` 固定为同源代理路径：

```powershell
$env:VITE_API_BASE_URL = "/api"
```

这样前端请求会走 `http://127.0.0.1:5174/api/...`，再由 Vite proxy 转发到 `http://127.0.0.1:8001/api/...`，避免备用端口下的 CORS 问题。

重启和验证结果：

- 后端监听：`8001`，PID `5448`。
- 前端监听：`5174`，PID `27176`。
- `GET http://127.0.0.1:8001/api/health` 返回 `status=ok`。
- `GET http://127.0.0.1:5174/api/health` 返回 `status=ok`。
- `curl.exe -I http://127.0.0.1:5174` 返回 HTTP 200。

如果浏览器仍显示旧的 `API未连接`，优先强制刷新页面，避免使用改动前的 Vite HMR/浏览器缓存状态。

## 2026-08-15 GitHub 推送说明

用户询问如何 push 到自己的 GitHub。本次只提供操作说明，没有执行 git 操作。

推荐流程：

1. 先在 GitHub 创建一个空仓库，例如 `Value_Investment`，不要勾选自动生成 README、`.gitignore` 或 License，避免和本地已有文件冲突。
2. 在本地项目根目录执行状态检查：

```powershell
cd D:\study\Python.Project\Value_Investment
git status
```

3. 如本地还没有远程仓库，添加 GitHub remote：

```powershell
git remote add origin https://github.com/<你的用户名>/Value_Investment.git
```

如果已经存在 remote，则用：

```powershell
git remote -v
git remote set-url origin https://github.com/<你的用户名>/Value_Investment.git
```

4. 检查 `.gitignore`，确认不要提交本地环境、缓存、日志和数据库私有数据，例如 `.venv/`、`node_modules/`、`.env`、`logs/`、`*.db`、`data/cache/` 等。
5. 首次提交：

```powershell
git add .
git commit -m "Initial value investment workspace"
```

6. 推送到 GitHub：

```powershell
git branch -M main
git push -u origin main
```

如果 GitHub 需要登录，推荐使用 Git Credential Manager 的浏览器授权，或使用 GitHub Personal Access Token 作为 HTTPS 密码。

注意：本项目包含本地研究数据和可能的模型配置，推送前应复核 `.env`、数据库文件、日志和原始数据，避免把 API Key、个人持仓、研究记录或敏感数据提交到公开仓库。
