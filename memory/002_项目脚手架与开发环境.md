# 002_项目脚手架与开发环境

## 环境基线

- Windows PowerShell
- Python 3.11+
- Node.js 与 npm
- 后端虚拟环境：`backend/.venv`
- 前端依赖目录：`frontend/node_modules`
- 本地数据库：`data/value_investment.db`

## 项目结构

```text
backend/app/
  api/routes/       FastAPI 路由
  analysis/         模型网关、Profile 与提示词
  core/             配置
  data_sources/     外部数据适配器
  db/               模型、初始化、迁移
  schemas/          Pydantic 合约
  services/         领域逻辑
  tests/            后端测试
frontend/src/
  app/               页面与工作区
  components/        通用组件
  services/          API 客户端
  styles/            全局样式
  tests/             前端测试
```

## 初始化与启动

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\setup.ps1
powershell -ExecutionPolicy Bypass -File .\scripts\dev.ps1
```

启动脚本支持只启动前端、只启动后端、强制重启和自定义端口。使用以下命令查看当前参数：

```powershell
Get-Help .\scripts\dev.ps1 -Detailed
```

默认前端为 `127.0.0.1:5173`。Vite 通过 `VITE_BACKEND_PORT` 把 `/api` 代理到后端；Vite 配置和启动脚本的标准默认后端端口均为 `8000`。端口被占用时由启动脚本注入本次实际端口，本地也可用被忽略的 `frontend/.env.local` 覆盖。

## 前端当前结构

- 概览：公司总数、当前研究对象、8/8 主链路和最近公司。
- 公司搜索：搜索、分页、选择和新增公司。
- 公司工作台：公司档案、财务底稿、公司公告、外部证据、分析师视角、投资备忘录、估值实验室和价格决策。
- 侧边栏入口和概览页主链路均映射到同一组工作区 section。
- 投资小工具：独立一级入口，内部注册“持仓组合”“买入备忘录”和“市场温度”，不依赖当前研究对象且不计入 8/8 主链路。
- 数据管理是独立运维页面，不依赖当前研究对象，也不计入概览页的 8 个研究模块。
- 当前研究对象保存在前端会话状态中；对象失效时返回搜索页。

## 配置

后端设置来自 `backend/.env`，使用 Pydantic Settings。默认数据库 URL 指向项目根目录 SQLite；默认 CORS 允许本机 `5173`。

014 多市场数据依赖已固定 `akshare==1.18.81`，并安装 `pypdf>=5,<7` 用于 HKEX PDF 正文提取。AKShare/pandas 只允许存在于港股 Provider 边界内，业务服务和固定测试使用项目 DTO，不直接依赖 DataFrame 或中文列名。

真实来源检查与默认测试分开：`scripts/smoke_sec.py` 显式检查 SEC（需要合规 `SEC_USER_AGENT`），`scripts/smoke_hk.py` 显式检查 AKShare/HKEXnews，可选 `--fetch-first-document` 下载并提取首份 PDF，`scripts/smoke_fx.py` 显式检查 ECB 日度参考汇率；pytest 不调用这些命令。015 的 Cboe VIX、恒生 VHSI 和 AKShare QVIX Provider 同样使用固定 fixture 做自动测试，真实刷新只在运行态显式触发。

数据库备份默认目录为 `data/backups/`，可通过 `VALUE_INVESTMENT_BACKUP_DIRECTORY` 覆盖。自动备份的启用状态、间隔小时和保留数量由数据管理 API 写入备份目录中的 `settings.json`。

模型相关变量：

```dotenv
MODEL_BASE_URL=
MODEL_API_KEY=
MODEL_NAME=
MODEL_WIRE_API=chat_completions
MODEL_REASONING_EFFORT=max
MODEL_DISABLE_RESPONSE_STORAGE=false
MODEL_TIMEOUT_SECONDS=180
```

DeepSeek 使用 Chat Completions 时，配置 `MODEL_REASONING_EFFORT=low/high/max` 会在请求体中同时发送 `thinking.type=enabled` 和对应的 `reasoning_effort`；配置为 `none` 时发送 `thinking.type=disabled`。当前本机 `deepseek-v4-pro` 使用思考模式 `max`。

## 验证流程

```powershell
Set-Location backend
.\.venv\Scripts\python.exe -m ruff check app
.\.venv\Scripts\python.exe -m pytest

Set-Location ..\frontend
npm test
npm run build
```

运行态验证至少检查：

1. `/api/health` 返回服务名和版本。
2. 概览页能读取公司池并进入 8 个研究模块。
3. 前端通过 `/api` 代理访问后端，没有 CORS 或端口错配。
4. 投资小工具能完成持仓人、快照、具体 Listing 持仓维护、估值刷新、011 结果导入买入备忘录和三市场温度刷新。
5. 桌面与移动宽度下无文字覆盖、整页横向溢出或不可操作控件，桌面左侧导航保持固定。

## 当前限制

- 开发脚本面向 Windows 本地环境，不是生产部署方案。
- 长耗时模型调用在 HTTP 请求内执行，尚无后台任务队列。
- SQLite 和单进程服务适用于个人研究，不适合多用户并发。
- 日志以开发期控制台和脚本日志为主，尚未统一结构化追踪。
