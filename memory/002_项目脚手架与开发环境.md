## 手动启动命令

### 首次初始化

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
```

```powershell
cd frontend
npm install
```

### 日常启动

```powershell
cd backend
.\.venv\Scripts\Activate.ps1
python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

```powershell
cd frontend
npm run dev -- --host 127.0.0.1 --port 5173
```

备注：旧版 `scripts/dev.ps1` 使用 `Start-Job + Receive-Job`，会把 `uvicorn` 的正常启动日志误包装成 `NativeCommandError`。当前版本已改成 `Start-Process + 独立日志重定向`，并在启动前检查 8000 和 5173 端口是否已被占用。

日志文件：

- `logs/backend.out.log`
- `logs/backend.err.log`
- `logs/frontend.out.log`
- `logs/frontend.err.log`

## 2026-08-14 22:31 +08:00 API 连接修复

用户反馈前端显示：

```text
加载失败
NetworkError when attempting to fetch resource.
API未连接
```

排查结果：

- 后端直连 `GET http://127.0.0.1:8001/api/health` 正常返回 `status=ok`。
- 前端代理 `GET http://127.0.0.1:5174/api/health` 也能正常返回 `status=ok`。
- 问题原因是 `scripts/dev.ps1` 在启动前端时设置了 `VITE_API_BASE_URL=http://127.0.0.1:8001/api`，导致浏览器从 `5174` 页面跨端口直连 `8001`。后端默认 CORS 只放行 `5173`，在备用端口 `5174` 下会触发浏览器侧 `NetworkError`。

已修复：

- 修改 `scripts/dev.ps1`，将开发环境中的 `VITE_API_BASE_URL` 固定为同源代理路径：

```powershell
$env:VITE_API_BASE_URL = "/api"
```

这样前端请求会走 `http://127.0.0.1:5174/api/...`，再由 Vite proxy 转发到 `http://127.0.0.1:8001/api/...`，避免备用端口下的 CORS 问题。

重启和验证结果：

- 后端监听：`8001`，PID `5448`。
- 前端监听：`5174`，PID `27176`。
- `GET http://127.0.0.1:8001/api/health` 返回 `status=ok`。
- `GET http://127.0.0.1:5174/api/health` 返回 `status=ok`。
- `curl.exe -I http://127.0.0.1:5174` 返回 HTTP 200。

如果浏览器仍显示旧的 `API未连接`，优先强制刷新页面，避免使用改动前的 Vite HMR/浏览器缓存状态。
