# 012_数据管理

## 模块定位

012 是本地 SQLite 的独立运维模块，不属于 `004-011` 研究主链路。概览页保持 `004-011 / 8 / 8`；侧边栏提供独立“数据管理”入口，页面标题为“数据管理”。

## 安全协议

破坏性操作采用两阶段协议：

1. Preview 根据当前数据库生成各表影响数量、受保护记录、预计释放空间、确认短语和十分钟有效的一次性令牌。
2. Execute 同时提交令牌和精确确认短语。后端重新计算数据库状态摘要；令牌过期、重复使用或数据库状态变化都会拒绝执行。

令牌绑定操作类型、参数和数据库状态。维护闸门保证同一时刻只有一个维护操作；进入维护后等待已有写请求结束，并让新的普通写请求返回 `503`。并发维护返回 `409`。破坏性数据库操作默认先创建并校验备份。

## 清理语义

### 单家公司

保留 `Company` 的证券身份、档案和行情，按依赖顺序删除该公司的 `PriceDecisionRun`、`ValuationRun`、`InvestmentMemo`、`AnalysisRun`、`Evidence`、`Announcement` 和 `FinancialStatement`，不影响其他公司。

### 全局分析历史

保留全部 `Company`、`FinancialStatement`、`Announcement`、`Evidence`，同时保留 Evidence 和公告诊断运行。只删除 `run_type=analyst_view`、`run_type=investment_memo` 及全部 Memo、估值和价格决策。

### 版本保留

支持单公司或全部公司，`N` 范围为 `1-100`。`AnalysisRun` 按公司、`run_type`、`analyst_profile` 分组；其他版本按公司分组。计划始终保护：

- `is_latest` 分析运行和 Memo，以及当前最新估值、价格决策。
- `archived` Memo。
- 被保留的价格决策引用的估值和 Memo。
- 被保留的估值引用的 Memo。
- 被保留 Memo 的版本链父记录、生成运行和 `source_analyst_run_ids` JSON 来源。
- 被保留 AnalysisRun 的 `parent_run_id` 父版本。

执行顺序为 `PriceDecisionRun -> ValuationRun -> InvestmentMemo -> AnalysisRun`。

### 软删除清理

物理删除 `status=deleted` 的价格决策，以及没有被估值、价格决策或 Memo 版本链引用的 deleted Memo。`archived` Memo 永不作为垃圾。被引用记录在 Preview 中显示阻塞原因。删除提交后执行 integrity check、`VACUUM` 和 `ANALYZE`，并返回压缩前后大小。

## 备份与恢复

默认目录为 `data/backups/`。每份备份使用 SQLite Backup API 创建，目录包含 `database.sqlite3` 和 `manifest.json`。manifest 保存备份 ID、UTC 创建时间、文件名、大小、SHA-256、SQLite schema version、所有业务表记录数、创建原因和应用版本。

支持手动创建、列表、SHA-256/完整性校验、两阶段恢复和两阶段删除。恢复前创建 `before_restore` 备份；目标恢复失败时自动恢复该备份。恢复成功后执行 integrity check 并返回 `restart_required=true`。

自动备份设置包括启用状态、`1-720` 小时间隔和 `1-200` 份保留数量。后台线程随应用启动和关闭，等待期间不阻塞 API；自动备份也使用维护锁。

## 数据库初始化

完整初始化要求确认短语“完整初始化数据库”。执行时先备份并校验，随后关闭当前会话、重建 SQLAlchemy 表、执行当前轻量迁移、写入 61 家标准公司种子并执行 integrity check。任一步失败都会从操作前备份恢复。成功响应包含 `restart_required=true`。

## API

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| `GET` | `/api/data-management/summary` | 数据库和备份概览 |
| `POST` | `/api/data-management/operations/preview` | 生成操作计划与令牌 |
| `POST` | `/api/data-management/operations/execute` | 执行令牌绑定操作 |
| `GET/POST` | `/api/data-management/backups` | 备份列表与手动创建 |
| `POST` | `/api/data-management/backups/{backup_id}/verify` | 校验备份 |
| `POST` | `/api/data-management/backups/{backup_id}/restore/preview` | 恢复预览 |
| `DELETE` | `/api/data-management/backups/{backup_id}` | 使用预览令牌删除备份 |
| `GET/PUT` | `/api/data-management/settings` | 自动备份设置 |

参数配置中心独立使用 `/api/parameter-config` API。当前生效参数存放在固定源码文件 `backend/app/configuration/active_parameters.json`，不属于 SQLite 备份；008-011 的运行参数快照仍随数据库备份和恢复。旧 `parameter_config_versions` 表为数据库兼容保留，但初始化和配置流程不再写入该表。

## 前端

页面包含数据库概览、公司清理、全局分析历史、版本保留、备份恢复和数据库维护六个区域。真实影响数量和阻塞原因均来自后端。危险操作在对话框内展示计划，并要求输入后端返回的确认短语；页面区分 loading、success、error、blocked 和 restart-required 状态。

## 参数配置中心

配置中心是独立工作台页面，覆盖数据采样、财务预警、分析师引擎、规则矩阵、Memo 决策、估值模型和价格决策七个域。所有参数在所属域内直接展示，不区分普通/专家模式；百分数以 UI 百分比编辑、后端小数存储；支持单项/分组恢复默认、完整校验、警告二次确认和直接发布源码参数。

编辑过程只存在于浏览器内存，不调用写接口；关闭或刷新页面即丢弃，不留草稿、版本或历史记录，也不影响运行。确认发布后，后端先执行完整结构校验，再用同目录临时文件和原子替换覆盖 active_parameters.json。运行期只接受通过完整校验的源码参数，否则整包回退内置默认配置并记录原因。

当前合同：

- 默认配置包含 375 个实际计算数值、0 个 audit_only 数值。
- 规则矩阵固定 8 位分析师、32 条规则、13 个维度和 117 个实际系数；32 条全部参与计算。
- 五状态同时包含 pass、neutral、unknown、warn、fail。
- 动态安全边际属于 010，最终范围 10%-50%；009 不再含评分或安全边际配置。
- 010 的 `valuation_models.normalization_year_weights` 是 FCF、净利润和年度所有者盈余共用的最近三年权重，默认 `50%/30%/20%`；缺少年度时运行时重新归一化，只影响新 010 估值。
- 010 的公司动态增长来源、原始值、边界裁剪值和分析师增量写入估值运行审计，不混入参数中心。
- 旧 parameter_impacts、price_reference、valuation_signal_pack 和 009 评分参数不展示、不编辑、不参与运行时计算。
- 所有历史运行继续读取自身 config_hash/config_snapshot；发布只影响后续新运行。
- 数据库迁移保留历史分析、Memo、估值和价格决策，不为旧评分伪造 0 值。

API 仅包括 GET /current、GET /defaults、POST /validate 和 PUT /current。旧草稿、版本、历史和回滚路由已移除。前端入口为“参数配置”，实现文件为 frontend/src/app/ParameterConfigView.tsx。

前端显示要求：

- 参数名称、作用说明、默认值、风险等级、字符串选项、规则角色和 13 个估值维度全部使用中文。
- 作用说明按真实代码路径说明触发条件、计算公式、增减方向、单位和下游影响。
- 数值最多按 10 位小数归整；只有真实比例字段显示为百分比。
- 规则矩阵按固定 8 人顺序展示 32 条规则；手机端逐条纵向布局，不依赖页面横向滚动。
- 分析师和维度筛选使用原生下拉；参数名称可换行，不截断。
