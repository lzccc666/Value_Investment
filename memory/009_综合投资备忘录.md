# 009_综合投资备忘录

## 本轮目标

本聊天框开始 `009_综合投资备忘录` 模块。当前先给出架构方案，不直接实现业务代码。

本方案已阅读并承接：

- `001_价值投资分析师系统架构.md`
- `005_公司详情财务.md`
- `006_公告导入与摘要.md`
- `007_外部信息智能搜索与证据库.md`
- `008_分析师视角引擎.md`

## 模块定位

009 是“综合投资备忘录”模块，负责把 008 已生成的多个独立分析师视角合成为一份可阅读、可编辑、可追溯的研究备忘录。

它回答：

- 多个投资框架在哪些判断上一致？
- 哪些判断存在分歧，分歧来自证据不足、框架差异，还是公司本身复杂？
- 当前最大风险、反方证据、数据缺口和待复核问题是什么？
- 后续进入 010 无锚定估值实验室时，需要准备哪些估值假设和输入？

它不回答：

- 当前价格是否便宜。
- 是否买入、卖出、持有、减仓。
- 建议仓位是多少。
- 短期价格走势或市场情绪判断。

所有买卖和仓位动作继续留给 `011_价格对照与投资决策`。

## 与前序模块边界

### 005 财务

009 不直接重新计算财务指标。财务质量判断主要来自 008 各分析师视角中已经结构化输出的：

- `financial_observations`
- `risk_flags`
- `data_gaps`
- `valuation_assumption_suggestions`
- `valuation_assumption_details`

如需追溯财务底稿，009 通过 008 run 的 `input_snapshot`、`analysis_basis.financial_periods` 和 `data_snapshot_hash` 回看当时使用的财务证据包版本。

### 006 公告

009 不重新读取公告正文、不重新摘要公告。公告证据通过 008 的：

- `announcement_observations`
- `rule_checks[].announcement_ids`
- `analysis_basis.announcement_ids`

进入综合备忘录。

### 007 外部 Evidence

009 不触发联网搜索，不生成搜索 query，不调用搜索 provider。

外部证据只通过 008 最新成功 `analyst_view` 的：

- `supporting_evidence_ids`
- `rule_checks[].evidence_ids`
- `analysis_basis.external_evidence_ids`
- `risk_flags`
- `counter_evidence`

进入综合备忘录。

如果 007 只提供 `search_lead`，009 必须把它标成“待人工复核线索”，不得写成已验证事实。

### 008 分析师视角

009 的主输入是同一家公司最新成功的多个 `analyst_view` run。

当前 008 的策略是每家公司每个 Profile 只保留最新一条 `analyst_view` 记录，因此 009 应按以下口径读取：

- `run_type="analyst_view"`
- `status="success"`
- 每个 `analyst_profile` 取当前最新记录
- 忽略 `status="failed"` 的视角，但在备忘录数据缺口中提示缺失的 Profile

009 可以读取 008 run 的模型输出和输入快照摘要，但不修改 008 run。

## 核心设计原则

1. 不简单平均分  
   综合结论不能把多个视角分数做算术平均。应先识别共识、分歧、关键风险和证据缺口，再形成研究结论。

2. 模型输出和用户编辑分开保存  
   模型生成的 memo 是审计记录，用户编辑后的 memo 是人工版本。二者不能互相覆盖。

3. 可追溯  
   每条综合判断都应能追溯到来源分析师 run、公告 id、外部 Evidence id 或财务期间。

4. 可反驳  
   备忘录必须保留反方证据、失效信号和后续复核问题。

5. 估值和决策隔离  
   009 只能整理估值假设建议，不得输出价格对照结论、买卖建议或仓位建议。

6. 版本化  
   每次自动生成和每次用户保存编辑都应形成新版本，不覆盖旧版本。

## 推荐数据模型

### 继续复用 AnalysisRun 记录生成审计

自动生成备忘录时创建一条新的 `analysis_runs` 记录：

```text
run_type = "investment_memo"
analyst_profile = "investment_committee"
run_version = "009_v1"
prompt_version = "investment_memo_v1"
status = "success" | "failed"
is_latest = true
```

`AnalysisRun` 保存：

- 本次生成使用的输入快照。
- 模型名称和 prompt 版本。
- 数据快照 hash。
- 模型原始结构化输出。
- 失败原因和错误类型。

009 的 memo run 不应覆盖旧 run。和 008 不同，综合备忘录天然需要历史版本。

### 新增 InvestmentMemo 保存可编辑版本

建议新增 `investment_memos` 表，用于保存模型生成版本和用户编辑版本：

```text
InvestmentMemo
  id
  company_id
  generation_run_id
  parent_memo_id
  version_no
  editor_type              # model | user
  title
  conclusion
  sections                 # JSON，结构化备忘录正文
  markdown                 # 可选，方便前端编辑和导出
  source_analyst_run_ids   # JSON
  source_snapshot_hash
  change_note
  status                   # draft | final | archived
  is_latest
  created_at
  updated_at
```

设计意图：

- `AnalysisRun.result` 保存模型输出，作为审计记录。
- `InvestmentMemo.sections/markdown` 保存当前可编辑文本版本。
- 用户每次保存编辑都创建新的 `InvestmentMemo`，`parent_memo_id` 指向上一版。
- `is_latest=true` 只用于快速读取最新版本，不代表旧版本被删除。

## 综合规则

服务层先做确定性聚合，再交给模型生成文稿。

建议规则：

- 同一主题被 2 个及以上 Profile 提及，进入 `consensus_candidates`。
- 同一主题在不同 Profile 中分别出现 `pass/warn/fail`，进入 `dissent_candidates`。
- 任一 Profile 出现管理层诚信、现金流恶化、杠杆压力、重大监管、会计口径复杂、永久性损失等风险，进入 `critical_risk_candidates`。
- `confidence` 低或 `data_gaps` 重复出现的主题，进入 `data_gap_candidates`。
- `valuation_assumption_details` 合并去重后进入 `valuation_assumption_queue`，供 010 消费。

研究结论建议使用枚举：

- `优质`
- `普通`
- `存疑`
- `回避`
- `需复核`

结论约束：

- 分析师视角不足 2 个时，默认不得高于 `需复核`。
- 多个关键主题证据缺口时，默认不得高于 `存疑` 或 `需复核`。
- 出现重大诚信、监管、现金流或偿债风险时，必须显式写入最大风险。
- 即使综合结论为 `优质`，也不得输出买入或仓位动作。

## 后端架构

建议新增文件：

- `backend/app/analysis/prompts/memo.py`
- `backend/app/schemas/memo.py`
- `backend/app/services/memo_service.py`
- `backend/app/api/routes/memos.py`

核心函数：

```text
build_investment_memo_snapshot(db, company)
build_committee_ledger(source_analyst_runs)
run_company_investment_memo(db, company, user_note=None, gateway=None)
list_company_investment_memos(db, company, limit, offset)
get_latest_company_investment_memo(db, company)
create_investment_memo_revision(db, memo, sections, markdown, change_note)
archive_investment_memo(db, memo)
```

校验重点：

- 只读取最新成功的 `analyst_view`。
- 不读取 `evidence_search` run 作为直接综合输入。
- 不触发外部搜索或公告摘要。
- 模型引用的 `source_run_ids` 必须来自本次快照。
- 模型引用的 `evidence_ids`、`announcement_ids`、`financial_periods` 必须来自来源分析师 run 的 `analysis_basis` 或 `rule_checks`。
- 输出字段中不得出现买入、卖出、持有、减仓、仓位建议等动作型结论。
- 保存用户编辑时不得修改模型生成的 `AnalysisRun.result`。

## 前端架构

建议在公司工作台新增“综合备忘录”区块，位置放在分析师视角之后、估值实验室之前。

页面能力：

- 显示最新 memo。
- 显示来源分析师视角数量和缺失 Profile。
- 一键生成综合备忘录。
- 编辑当前 memo。
- 保存为新版本。
- 查看历史版本。
- 显示来源 run id、生成时间、数据快照 hash 和 prompt 版本。
- 显示“尚未完成估值/价格对照”的状态，避免误解为投资动作建议。

建议前端类型和 API client 增加：

- `InvestmentMemo`
- `InvestmentMemoListResponse`
- `InvestmentMemoGenerateResponse`
- `getLatestInvestmentMemo`
- `getInvestmentMemos`
- `generateInvestmentMemo`
- `createInvestmentMemoRevision`
- `archiveInvestmentMemo`

## MVP 落地顺序

1. 后端新增 memo schema、prompt、service 和 API。
2. 数据库新增 `investment_memos` 表和迁移逻辑。
3. 生成 memo 时读取最新成功的 008 分析师 run，构建 `committee_ledger`。
4. 调用 `ModelGateway.generate_structured(...)` 生成结构化 memo。
5. 写入 `AnalysisRun(run_type="investment_memo")` 和 `InvestmentMemo(editor_type="model")`。
6. 前端新增综合备忘录区块，支持生成、展示、编辑和版本列表。
7. 增加后端和前端测试。

## 测试计划

后端测试：

- 无公司时返回 404。
- 没有成功 `analyst_view` 时不能生成 memo，并给出清晰错误。
- 只读取最新成功 `analyst_view`，忽略失败 run。
- 多 Profile 输入能生成 `committee_ledger`。
- memo run 不覆盖旧 `investment_memo` run。
- 自动生成后创建 `InvestmentMemo` 最新版本。
- 用户编辑保存创建新版本，不修改原始模型 run。
- 模型输出引用不存在的 run/evidence/announcement/financial period 时失败并记录错误。
- 模型输出买卖或仓位动作时失败。

前端测试：

- 无 memo 时显示生成入口。
- 有 memo 时显示最新版本。
- 生成成功后刷新最新 memo。
- 生成失败时显示错误。
- 编辑保存后刷新为新版本。
- 历史版本入口显示版本列表。
- 价格对照状态显示为未开始，不展示买卖或仓位动作。

## 当前架构决策

- 009 不新增搜索、采集或公告摘要能力。
- 009 主输入只来自最新成功的 008 分析师视角。
- 自动生成审计使用 `AnalysisRun(run_type="investment_memo")`。
- 可编辑正文使用新增 `InvestmentMemo` 版本表。
- 模型输出和用户修订分离保存。
- 009 只输出研究备忘录、复核问题和估值假设队列，不输出交易动作。
- 009 为 010 提供结构化 `valuation_assumption_queue`，为 011 保留清晰的价格决策边界。
