# 009_综合投资备忘录

## 模块职责

009 汇总 008 的最新成功分析，生成可追溯的投资委员会备忘录。它负责共识、分歧、风险、缺口、分析师评分和动态安全边际建议，但不计算内在价值，也不生成交易动作。

## 生成条件与输入

- 至少需要 2 个成功的分析师视角。
- 每个 Profile 只使用最新成功运行；最新失败不会遮蔽此前成功结果。
- 输入仅来自已保存的 008 运行，不重新搜索、采集或摘要公告。
- 所有引用必须指向输入快照中的财务报告期、公告 ID、Evidence ID 或分析运行。

## 委员会账本

后端先确定性构建 `committee_ledger`，再交给模型组织 Memo。账本包含：

- 成功与失败 Profile
- 共享证据、公告和财务报告期
- 共识候选、分歧候选和关键风险
- 数据缺口与估值假设队列
- `analyst_scorecard`

模型不能改变账本中的来源关系，也不能输出买入、卖出、持有、加减仓等动作。

## 分析师评分

40 条规则等权，每条权重为 `1/40`。状态分为：

| 状态 | 分数 |
| --- | ---: |
| `pass` | `1.0` |
| `warn` | `-0.3` |
| `fail` | `-2.0` |
| `unknown` | `-0.1` |

综合分数：

```text
total_score = sum(rule_status_score * 1/40)
```

建议安全边际：

```text
clamp(((1 - total_score) / 3) * 0.50, 0.0, 0.50)
```

评分不使用 `data_confidence` 或 `profile_fit_score` 作为权重，确保规则等权可解释。安全边际只作为 011 的建议输入，不进入 010 内在价值计算。

## Memo 输出

- 研究结论和执行摘要
- 共识、分歧、积极证据和反方证据
- 关键风险、数据缺口和待验证问题
- 估值假设队列
- 置信度摘要和来源引用
- 分析师评分卡与建议安全边际
- Markdown 渲染结果

`valuation_signal_pack` 仅保留兼容字段并标记 deprecated；010 不再读取它。

## 版本管理

- 每次生成创建新的 `InvestmentMemo` 和对应 `AnalysisRun`。
- `version_no`、`parent_memo_id`、`is_latest` 和来源哈希记录版本关系。
- 归档或删除最新版本后重新计算当前 latest。
- 当前没有手工编辑 Memo 正文的接口。

## API

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| `POST` | `/api/companies/{company_id}/investment-memos/generate` | 生成新版本 |
| `GET` | `/api/companies/{company_id}/investment-memos/latest` | 最新有效 Memo |
| `GET` | `/api/companies/{company_id}/investment-memos` | 历史列表 |
| `GET` | `/api/investment-memos/{memo_id}` | Memo 详情 |
| `POST` | `/api/investment-memos/{memo_id}/archive` | 归档 |
| `DELETE` | `/api/investment-memos/{memo_id}` | 删除 |

## 当前限制

- Memo 必须依赖模型配置，模型失败时不会生成半成品版本。
- 评分是规则状态聚合，不代表概率、预期收益或投资评级。
- 009 不比较市场价格，结论必须保持 price-blind。

## 前端行为

- 最新综合备忘录不显示“研究结论”“来源视角”“状态”三项摘要字段。
- 版本、生成时间、标题、执行摘要、分析师评分和其他 Memo 正文继续显示。
