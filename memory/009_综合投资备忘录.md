# 009_综合投资备忘录

## 模块定位

009 位于分析师视角引擎（008）和无锚定估值实验室（010）之间，负责把各分析师的最新一次有效判断组织成一份可追溯、可版本化的投资委员会备忘录。

009 是“模型综合 + 后端确定性规则”的混合模块：

- 模型负责组织执行摘要、核心判断、共识、分歧、风险、反方证据、数据缺口和估值假设复核项。
- 后端负责选择来源、构建委员会账本、计算 40 项分析师评分、映射动态安全边际、覆盖来源图并校验输出。
- 模型不能生成或修改分析师评分，也不能生成内在价值、目标价、买卖动作或仓位建议。

009 不计算内在价值。010 负责 price-blind 内在价值计算；011 才读取当前价格，并把 010 的内在价值与 009 的安全边际结合起来。

```text
008 最新分析师运行
        |
        v
009 输入快照 -> 确定性委员会账本 -> 模型综合叙事 -> 后端覆盖与校验
        |                                      |
        |                                      v
        |                              InvestmentMemo 历史版本
        v                                      |
010 读取最新有效 Memo 上下文 + 直接读取最新 008 参数矩阵
                                               |
                                               v
                             011 读取 010 绑定的固定 Memo 评分与安全边际
```

## 输入选择规则

### 分析师运行的“最新”语义

009 只读取 `run_type="analyst_view"` 的 008 运行。后端先按 Profile 分组，再按 `created_at DESC, id DESC` 选择每个 Profile 的最新一次运行，最后按状态分为成功和失败。

这意味着：

- Profile 最新一次运行成功：进入 009 来源；更早的失败不会继续显示为“最近失败”。
- Profile 最新一次运行失败：不使用更早的成功结果兜底，该 Profile 本次不可用于综合，并标记为最近失败。
- 从未运行或没有最新成功结果的 Profile：作为缺失视角处理。
- 009 不读取 `evidence_search` 等其他 `run_type`，也不读取历史 Memo 作为生成素材。

当前默认至少需要 `2` 个最新成功分析师视角；不足时后端拒绝生成，不调用模型。

### 送入模型的快照

`build_investment_memo_snapshot()` 保存以下内容：

- 公司身份信息：代码、交易所、名称、行业、简介、上市日期、状态和标签。
- 每个成功 008 来源的运行 ID、Profile、生成时间、快照哈希、置信度和适配度。
- 008 结果的精简字段：总览、关键观察、40 项规则检查、财务观察、公告观察、风险、反方证据、估值假设、数据缺口、后续问题和分析依据。
- 后端生成的 `committee_ledger`。
- 来源边界、最少成功 Profile 数和运行时配置标识。

公司当前价格、市值、历史价格、估值倍数、持仓成本、券商评级和市场情绪不进入 009 快照。

## 前端准备区与更新时机

“综合备忘录准备区”不是某个历史 Memo 的内容，而是前端根据当前加载的最新 008 运行实时计算的预览。

| 准备区项目 | 当前来源 | 何时变化 |
| --- | --- | --- |
| 可用于综合的成功视角 | 各 Profile 最新一次运行中的成功项 | 008 新生成、重跑成功/失败或删除运行后刷新 |
| 缺失或失败视角 | 没有最新成功结果的 Profile；最新失败者额外显示“最近失败” | 008 最新运行状态变化后刷新 |
| 风险汇总 | 最新成功 008 的 `risk_flags`，按文本去重 | 008 成功结果变化后刷新 |
| 反方证据 | 最新成功 008 的 `counter_evidence`，按文本去重 | 008 成功结果变化后刷新 |
| 数据缺口 | 最新成功 008 的 `data_gaps`，按文本去重 | 008 成功结果变化后刷新 |
| 估值假设建议 | 最新成功 008 的 `valuation_assumption_suggestions`，按文本去重 | 008 成功结果变化后刷新 |

每个准备区块在前端最多展示 `8` 条，但后端生成快照不受这个前端展示上限影响。

手工修改 008 的 `pass / warn / fail / unknown` 会立即写回该 008 运行，并重算它的估值参数矩阵，但不会原地修改已经保存的 Memo。要让 Memo 评分、分歧和安全边际反映新状态，必须重新生成 009。

## 确定性委员会账本

模型调用前，后端通过 `build_committee_ledger()` 构建可审计账本。模型可以据此写作，但不能改变其来源边界。

### 来源集合

账本汇总并去重：

- `source_run_ids`
- `shared_evidence_ids`
- `shared_announcement_ids`
- `financial_periods`
- 成功 Profile 数和缺失/失败 Profile

来源 ID 来自 008 的 `analysis_basis` 和各 `rule_checks`。生成后的 `source_map` 会被后端用账本内容强制覆盖，不接受模型自行扩展来源。

### 共识与分歧候选

- 关键观察、财务观察和公告观察会去除末尾标点并取前 `30` 个字符作为主题键。
- 同一主题至少被提及 `2` 次，且来自至少 `2` 个 Profile，才成为共识候选。
- 同一 `rule_id` 在不同 Profile 间出现至少两种状态时，成为分歧候选。

这些只是提供给模型的候选结构，不等同于统计显著性，也不自动代表最终研究结论。

### 风险、缺口和估值复核项

- 风险包含“诚信、现金流恶化、杠杆、偿债、监管、会计、永久性损失”等关键词时，优先进入关键风险候选。
- 若没有命中关键风险词，则使用最先汇总的最多 `6` 条风险作为候选。
- 数据缺口按完整 `summary` 文本去重。
- 优先读取 008 的结构化 `valuation_assumption_details`；没有时，把旧式 `valuation_assumption_suggestions` 转成 `review_only` 项。
- 估值复核项按 `(assumption_type, reason)` 去重，并自动补入来源分析运行 ID。

### 分析师评分卡

`analyst_scorecard` 由后端直接加入账本。模型提示词明确禁止推断、重算或叙事调整该评分；模型返回后，服务还会再次用账本评分卡覆盖模型字段。

## 模型职责与结构化输出

### 模型负责什么

当前提示词版本为 `investment_memo_v1`。模型仅使用输入 JSON 快照，负责输出：

- `title`、`research_conclusion`、`executive_summary`
- `core_thesis`
- `consensus_points`、`dissent_points`
- `business_quality`、`financial_quality`
- `management_and_capital_allocation`、`moat_and_growth`
- `key_risks`、`counter_evidence`
- `data_gaps`、`follow_up_questions`
- `valuation_assumption_queue`
- `watch_signals`
- `confidence_summary`

`research_conclusion` 只允许：`优质 / 普通 / 存疑 / 回避 / 需复核`。它是模型综合标签，不参与 009 评分公式，也不直接进入 010 或 011 的数值计算。

### 模型不能做什么

- 不搜索网页、不采集新数据。
- 不重新摘要公告、不重算财务指标。
- 不读取历史 Memo。
- 不生成 010 估值信号、内在价值或目标价值。
- 不输出买入、卖出、持有、加仓、减仓、仓位、目标价或当前价格贵贱判断。

### 输出兼容与后端覆盖

`InvestmentMemoOutput` 对常见模型差异做结构化归一化：

- 支持 `summary`、`overall_summary` 等常见字段别名映射到 `executive_summary`。
- 模型漏掉 `executive_summary` 时，会尝试从已有摘要、结论、标题或首个有效正文项派生，避免只因字段别名导致整次生成失败。
- 共识、分歧、估值复核项、来源引用和旧估值信号字段支持常见对象/列表/字符串形态的归一化。

归一化通过后，服务仍会确定性覆盖：

- `source_map`：以委员会账本为准。
- `analyst_scorecard`：以 40 项规则计算结果为准。
- `valuation_signal_pack`：固定写为空的 deprecated 兼容结构。

`valuation_signal_pack` 当前的 `source` 为 `deprecated_009_display_compatibility_only`，所有信号列表为空。010 不读取它。代码中仍保留旧信号构建与清洗函数用于兼容测试，但不在当前 Memo 生成主路径中。

### 输出长度与展示截断

当前没有对 Memo 总字数、数组条数或模型输出 token 设置 009 专用硬限制。提示词要求执行摘要为一段，实际长度由模型和上游素材决定。

数据库保存完整结构化 `sections` 和后端生成的 Markdown。前端为了可读性只展示部分内容：最新和历史详情中的普通列表最多显示 `5` 条，准备区每块最多显示 `8` 条；这不等于数据库内容被截断。

## 引用、结构和安全校验

模型输出在落库前依次经过以下检查：

1. Pydantic 结构校验和字段归一化。
2. 后端覆盖 `source_map`、`analyst_scorecard` 和 deprecated `valuation_signal_pack`。
3. 递归校验所有分析运行 ID、Evidence ID、公告 ID 和财务期间只能来自本次账本。
4. 递归扫描交易动作和价格判断禁止词；`prohibited_actions_note` 本身除外。

任一步失败都会把本次 `AnalysisRun` 标记为 `failed`，记录经过清洗的错误类型和错误文本，不创建半成品 `InvestmentMemo`。

## 40 项分析师评分

### 等权规则

当前系统有 `10` 个分析师 Profile，每个 Profile 固定 `4` 条规则，共 `40` 条。每条规则权重完全相同：

```text
rule_weight = 1 / 40 = 0.025
```

四状态分值：

| 状态 | 分数 | 含义 |
| --- | ---: | --- |
| `pass` | `+1.0` | 规则通过，正向贡献 |
| `warn` | `-0.3` | 需要观察，轻度负贡献 |
| `unknown` | `-0.1` | 证据不足，小幅负贡献 |
| `fail` | `-2.0` | 规则不通过，强负贡献 |

综合分数：

```text
total_score = sum(all_40_rule_status_scores * 1/40)
```

每个分析师有 4 条规则，因此展示上的 `analyst_weight` 固定为 `4/40 = 10%`：

```text
rule_score_total_i = sum(profile_i_four_rule_scores)
weighted_score_i   = rule_score_total_i / 40
total_score        = sum(weighted_score_i)
```

`data_confidence` 和 `profile_fit_score` 会保留在评分卡明细中用于审计，但不参与 009 权重。它们在 010 的分析师参数聚合中有独立用途，不能与 009 等权评分混用。

### 缺失与未知

- 成功运行中缺少某条规则、状态非法或状态为空时，该规则按 `unknown = -0.1` 计算。
- 没有成功来源的 Profile 仍保留在 10 人评分卡中，其 4 条规则全部按 `unknown` 计算。
- `coverage.known_rules` 不统计 `unknown`，但 `unknown` 仍进入总分和安全边际。

因此，来源覆盖不足不仅会显示在覆盖率中，也会通过未知分小幅提高安全边际。

### 动态安全边际

通用配置公式为：

```text
suggested_safety_margin = clamp(
    ((pass_score - total_score) / safety_margin_score_span)
    * safety_margin_max,
    safety_margin_min,
    safety_margin_max
)
```

当前参数代入后：

```text
suggested_safety_margin = clamp(
    ((1 - total_score) / 3) * 0.50,
    0.0,
    0.50
)
```

| 40 项全部为 | `total_score` | 建议安全边际 |
| --- | ---: | ---: |
| `pass` | `1.0` | `0%` |
| `unknown` | `-0.1` | `18.33%` |
| `warn` | `-0.3` | `21.67%` |
| `fail` | `-2.0` | `50%` |

在当前线性映射中，`total_score=0.4` 对应 `10%`，`total_score=0.1` 对应 `15%`。评分越差，建议安全边际越高；最终范围限制为 `0%-50%`。

这只是公司质量与证据完整度对应的安全边际建议，不是概率、预期收益率或投资评级。它不进入 010 的内在价值计算，只在 011 参与建议买入价计算。

## 生成与失败生命周期

一次生成按以下顺序执行：

1. 读取当前运行时参数，并形成配置快照和哈希。
2. 构建 008 来源快照、委员会账本和分析师评分卡。
3. 检查成功 Profile 数是否达到门槛。
4. 创建 `run_type="investment_memo"`、`status="running"` 的 `AnalysisRun`。
5. 调用模型生成结构化结果并完成后端覆盖、引用校验和禁止动作校验。
6. 将运行标记为 `success`，再创建新的 `InvestmentMemo` 版本。

生成请求可带 `user_note`，当前只保存到本次 `AnalysisRun` 供审计，不会加入模型输入快照或提示词，因此不改变 Memo 正文。

生成失败时：

- 本次 `AnalysisRun.status="failed"`，不创建 Memo。
- 上一个有效 `InvestmentMemo` 仍保持 latest，不会被失败结果覆盖。
- 最新的 Memo 生成运行可能是失败状态，而最新有效 Memo 仍是更早版本；两者是不同概念。

接口错误语义：

- 公司不存在：`404`。
- 来源不足或模型未配置：`400`。
- 模型调用失败或结构/引用/禁止动作校验失败：`502`。

## Memo 持久化与版本管理

### 每次成功生成均创建新版本

每次成功生成都会新增一条 `InvestmentMemo`，不会覆盖旧记录：

- `version_no` 使用该公司历史最大版本号加 `1`，删除或归档后也不复用旧版本号。
- 新版本 `editor_type="model"`、`status="draft"`、`is_latest=true`。
- 之前未删除、未归档的版本改为 `is_latest=false`，但继续保留在历史中。
- `status="draft"` 是当前 Memo 生命周期默认值，不表示模型仍在生成；生成是否成功看关联 `AnalysisRun.status`。
- 表结构保留 `parent_memo_id`，但当前模型生成路径固定写 `None`；当前版本顺序由 `company_id + version_no` 表达，不依赖父版本链。

Memo 保存：

- 标题、研究结论和完整 `sections`
- 后端生成的 Markdown
- 来源分析运行 ID 和来源快照哈希
- 生成运行 ID
- 配置版本、配置哈希和完整配置快照
- 版本号、状态、latest 标记和时间

### latest、归档与删除

“最新有效 Memo”只在 `status` 不是 `archived/deleted` 的记录中选择。

- 归档：软状态改为 `archived`，表示主动退出当前工作流。
- 删除：软状态改为 `deleted`，表示用户从常规界面移除。
- 两者当前都会从默认历史列表和新建 010 时的 latest 选择中排除，数据库记录不会物理删除。
- 归档或删除 latest 后，后端按 `created_at DESC, id DESC` 自动把前一个有效版本设为 latest；没有有效版本时返回空。
- 历史接口传 `include_deleted=true` 时可包含归档和删除记录，但当前前端不启用该参数。

如果某条 Memo 已经被 010 估值引用，011 会继续通过 `ValuationRun.memo_id` 读取这条固定记录，即使它后来被软归档或软删除；这样已有估值和价格决策仍可复现。归档或删除只影响后续新建 010 时选择哪个 latest Memo。

### 不可编辑边界

当前没有编辑 Memo 正文、修改研究结论或保存人工修订版的 API 和前端控件。需要反映新分析师状态、参数或上游数据时，应重新生成一个新版本。

旧 Memo 是不可变历史快照：修改 008、修改运行时参数或生成新 Memo 都不会反写旧版本。

## 前端实现

### 最新综合备忘录

前端展示：

- 版本号、参数版本/内置参数标识和生成时间
- 标题和执行摘要
- 分析师综合得分、覆盖 Profile 数、已判断规则数和动态安全边际
- 10 位分析师的四指标总分、固定占比和等权贡献
- 可展开的 40 项规则分值明细
- 核心判断、关键风险和估值输入队列

最新卡片不显示“研究结论”“来源视角”“状态”三个摘要字段，也不显示此前的交易边界警告文案。

### 历史分析记录

- 默认加载最近 `20` 条未归档、未删除 Memo，按创建时间倒序。
- latest 版本也会出现在历史列表中，并带“最新”标记。
- 每条显示版本、时间和标题，可展开查看摘要、评分卡、核心判断、风险、数据缺口和估值输入队列。
- 支持手工归档和删除；操作后重新请求 latest 和历史列表。
- 不提供编辑、保存新修订版或交易动作按钮。

### 前端刷新边界

- 生成 009 成功后，前端重新加载 latest 和历史 Memo。
- 归档或删除后，前端重新加载 latest 和历史 Memo，因此回退版本会立即显示。
- 手工修改 008 规则状态只更新当前 008 运行；已经显示的 Memo 不会同步变更。
- `not found` 生成错误会提示检查后端是否已加载 009 路由并重启服务；其他错误优先显示接口返回的具体校验信息。

## 与 008、010、011 的接口

### 008 -> 009

009 读取各 Profile 最新一次运行的成功结果。40 项规则状态既用于委员会分歧候选，也由后端计算 009 评分和安全边际。

推荐的上游变更顺序：

```text
生成/重跑 008 或手工修改规则状态
-> 重新生成 009
-> 新建或重算并确认 010
-> 生成 011
```

### 009 -> 010

新建 010 草稿时，010 读取当时的最新有效 Memo，并把 `memo_id` 固定保存到 `ValuationRun`。010 从 Memo 读取的上下文字段包括：

- Memo ID、版本号、标题和来源快照哈希
- `research_conclusion`
- `valuation_assumption_queue`
- `key_risks`
- `counter_evidence`
- `data_gaps`
- `follow_up_questions`
- `confidence_summary`
- `source_map`

010 的估值参数矩阵直接来自最新 008，不来自 009 的分析师综合分，也不读取 009 的 `valuation_signal_pack`。009 负责给 010 提供经过综合的风险、缺口和假设复核上下文，但不把动态安全边际混入内在价值。

因此，手工修改 008 状态后即使不重生成 Memo，新的 010 也可能读取到更新后的 008 参数矩阵；但它会同时绑定旧 Memo。为保持评分、安全边际、叙事和估值来源一致，应先重生成 009，再创建新的 010。

### 009 + 010 -> 011

011 不读取公司当前最新 Memo，而是读取所选 `ValuationRun.memo_id` 绑定的固定 Memo：

- 从 010 读取保守、中性、乐观每股内在价值。
- 从绑定 Memo 的 `analyst_scorecard` 读取 `total_score` 和 `suggested_safety_margin`。
- 再在 011 首次引入公司当前价格。

```text
scenario_buy_price = scenario_intrinsic_value * (1 - effective_safety_margin)
```

用户可以在 011 用 `0%-50%` 的人工值覆盖建议安全边际，但建议值、覆盖值和最终生效值会分别保存。若希望 011 使用新 Memo，必须先创建/重算一条绑定新 Memo 的 010，而不是只重新生成 009。

## 运行时参数与复现

| 参数 | 当前值 | 主路径作用 |
| --- | --- | --- |
| `memo_decision.min_successful_analysts` | `2` | 生成门槛 |
| `memo_decision.status_scores` | pass `1.0`、warn `-0.3`、unknown `-0.1`、fail `-2.0` | 40 项评分 |
| `memo_decision.safety_margin_min` | `0.0` | 安全边际下限 |
| `memo_decision.safety_margin_max` | `0.50` | 安全边际上限和线性缩放 |
| `memo_decision.safety_margin_score_span` | `3.0` | 安全边际映射分母 |
| `analyst_engine.model_temperatures.memo` | `0.20` | 模型综合温度，不改变后端评分 |
| `memo_decision.model_confidence_map` | low `0.35`、medium `0.65`、high `0.85` | 把模型置信等级写入 Memo `AnalysisRun.confidence` |

实现注意：

- `memo_decision.rule_weight_mode` 当前配置值为 `equal_weight_per_rule`，但代码固定执行 40 项等权，没有可切换的其他权重模式。
- `data_sampling.memo_list_items` 只被旧的估值信号兼容构建函数读取；由于当前主路径直接写空的 deprecated `valuation_signal_pack`，它不控制当前 Memo 模型输入或正文长度。
- 每次生成都会把运行时配置的 `config_version`（可能为空）、`config_hash` 和完整 `config_snapshot` 同时保存到 `AnalysisRun` 与 `InvestmentMemo`。
- 后续参数发布只影响新生成版本，不重算旧 Memo。

## 已知边界

- Memo 依赖模型配置；没有纯规则正文生成的兜底模式。
- 委员会共识使用前 30 字主题键和计数启发式，适合候选聚合，不是语义聚类模型。
- 当前没有 Memo 正文硬长度限制、人工编辑、归档恢复或删除恢复的前端流程。
- `status="draft"` 暂未形成更完整的发布/锁定状态机。
- 旧 `valuation_signal_pack` schema、归一化和构建函数仍在代码中，但当前业务主链路只保留空兼容字段。
- 评分衡量的是当前 40 项规则状态的线性聚合，不应解释为预测准确率、收益率或交易结论。
