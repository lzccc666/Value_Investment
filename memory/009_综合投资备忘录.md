# 009_综合投资备忘录

## 当前最新状态

009 综合投资备忘录 MVP 已实现，并在 2026-08-15 增强为可向 010 无锚定估值实验室传递逐分析师估值信号矩阵。本次最新热修已让模型自然语言/中文枚举值在 schema 入口归一化，避免贵州茅台 memo 因 `valuation_signal_pack.*_signal` 等字段返回“偏正面、较高风险、提高、现金流折现”这类值而被结构校验拦截；同时兼容 `valuation_method_preference`、`parameter_impacts` 和共识/分歧参数影响列表里直接出现字符串的情况。

重要边界：
- 应用内的 `investment_memos` 表保存历史 memo 版本；本 memory 文件只记录当前最新开发状态，不累积历史版本全文。
- 010 只读取最新未删除 memo；009 的历史 memo 可以在前端查看、删除或归档，但不会主动传给 010。
- 009 不输出买入、卖出、持有、减仓、加仓、仓位建议、目标价或价格对照判断。
- 009 可读取 008 中已有的价格相关分析，因为 008 边界允许；但写给 010 的 `valuation_signal_pack` 必须 price blind。

## 已实现能力

后端：
- 读取同一公司的最新成功 008 `analyst_view` runs，生成综合投资备忘录。
- 至少需要 2 个成功分析师视角，否则拒绝生成。
- 每次生成都会创建新的 `AnalysisRun(run_type="investment_memo")` 和新的 `InvestmentMemo(editor_type="model")`。
- 未删除 memo 中只允许一条 `is_latest=true`；删除或归档最新 memo 后，latest 自动回退到上一条未删除 memo。
- 提供 `get_latest_memo_for_valuation(db, company_id=...)`，供 010 读取最新未删除 memo；本轮未改变该函数逻辑。
- `InvestmentMemoOutput` 支持模型常见别名和外层包装兼容，避免因 `executive_summary` 或字段别名导致整次生成失败。
- `source_map` 和所有 `source_refs` 会校验，只能引用当前 009 输入快照里的 analyst run、Evidence、公告和财务期间。
- 保存前会校验交易动作禁词，避免 009 输出买卖、持有、仓位或价格决策动作。

前端：
- Memo 区支持生成、查看最新 memo、查看历史分析记录、展开历史详情、删除和归档历史记录。
- 前端不提供 memo 正文编辑能力。
- Memo 准备区来自当前前端加载的 008 最新 runs；真正保存到 memo 的内容只在点击“生成备忘录”并成功生成新 memo 时更新。

## valuation_signal_pack

本轮新增 `memo.sections.valuation_signal_pack`，面向 010 读取。它不替代 `core_thesis`、`key_risks`、`counter_evidence`、`data_gaps` 或 `valuation_assumption_queue`，而是新增机器可消费的估值信号中间层。

核心结构：
```json
{
  "price_blind_compatible": true,
  "source": "latest_successful_analyst_view_runs",
  "analyst_signals": [],
  "consensus_parameter_impacts": [],
  "dissent_parameter_impacts": [],
  "risk_constraints": [],
  "data_gaps_for_valuation": [],
  "user_confirmation_required": true
}
```

`analyst_signals` 会逐个保留每位最新成功分析师视角，不只保存综合结果。每项包含：
- `profile_id`
- `profile_name`
- `source_run_id`
- `profile_fit_score`
- `data_confidence`
- `business_quality_signal`
- `moat_durability_signal`
- `growth_runway_signal`
- `pricing_power_signal`
- `capital_intensity_signal`
- `cash_flow_reliability_signal`
- `balance_sheet_risk_signal`
- `management_capital_allocation_signal`
- `cyclicality_signal`
- `permanent_loss_risk_signal`
- `valuation_method_preference`
- `parameter_impacts`
- `source_refs`

生成策略：
- Prompt 要求模型输出 `valuation_signal_pack`，但服务层会基于最新成功 008 runs 强制生成基础矩阵，确保每位分析师不丢失。
- 模型输出可补充 `consensus_parameter_impacts`、`dissent_parameter_impacts`、`risk_constraints` 和 `data_gaps_for_valuation`，但保存前会统一 schema 校验、来源校验和 price-blind scrub。
- `parameter_impacts` 只表达参数方向、幅度等级、情景和复核理由，例如 `discount_rate up`、`scenario_spread widen`、`cash_flow_growth_rate review`；不输出估值数字。
- 所有参数建议都带 `requires_user_review=true`，顶层带 `user_confirmation_required=true`，不能直接进入 010 最终计算。
- `valuation_signal_pack` 应受 008 `rule_checks[].status` 影响。008 标准状态为 `pass / warn / fail / unknown`，前端中文可理解为“通过 / 观察或警惕 / 不通过或风险 / 未知”。这些状态不机械等同于某个估值参数，但应影响每位分析师信号的方向、强度、置信度和 `parameter_impacts`：
  - `pass`：支持正向质量信号、相关方法权重上调或情景区间收窄，但仍不能突破服务层硬边界。
  - `warn`：进入观察状态，通常扩大情景区间、提高折现率、降低置信度或要求用户复核。
  - `fail`：触发负向信号、保守情景、风险约束、折现率上调、方法权重下调或锁定前复核。
  - `unknown`：不做正向加分，增加 `requires_user_review`、数据缺口权重和置信度折扣。

Price-blind 规则：
- `valuation_signal_pack` 不得包含 `current_price`、`historical_price`、`market_cap`、`valuation_multiple`、`pe_ttm`、`pb_ratio`、`ps_ratio`、`position_cost`、`rating`、`target_price`、`market_sentiment` 等价格锚点字段或文本。
- 中文锚点如“当前价格”“历史价格”“市值”“估值倍数”“市盈率”“市净率”“市销率”“持仓成本”“评级”“目标价”“市场情绪”也会被剔除或改写。
- 允许保留结构字段名 `price_blind_compatible` 和 `pricing_power_signal`，因为它们不是价格输入。

## 2026-08-15 valuation_signal_pack 状态映射复核

用户追问当前 `valuation_signal_pack` 是否已经按“通过=positive、未知=unknown、不通过=negative、观察=neutral”直接映射。

复核结论：当前实现并不是直接读取 008 `rule_checks[].status` 做状态映射，而是在 `backend/app/services/memo_service.py` 的 `_build_analyst_valuation_signal(...)` 中把分析师输出拼成文本，再由 `_signal_from_terms(...)` 按关键词推断 `positive/neutral/negative/unknown`。并且当前规则是 `negative` 关键词优先于 `positive` 关键词。

这会导致贵州茅台这类样例出现明显误伤：
- `capital_intensity_signal` 的负向关键词包含 `capital expenditure/capex/资本开支/重资产`，只要分析师文本提到“资本开支”就可能被判为 `negative`，即使原意是“资本开支低”或“需复核未来资本开支”。
- `cyclicality_signal` 的负向关键词包含 `cyclical/macro/周期/宏观`，只要文本提到行业周期或宏观复核就可能被判为 `negative`。
- `balance_sheet_risk_signal` 的负向关键词包含 `debt/leverage/负债/杠杆/负债压力`，可能覆盖“净现金、低负债”的正向判断。

后续修正方向：
- 009 服务层应优先从 008 `rule_checks[].status` 和结构化分析结论生成维度信号，文本关键词只能作为缺失字段的兜底，不应覆盖明确状态。
- 若继续采用用户要求的 010 分值 `通过 +1、观察 -0.35、不通过 -2、未知 0`，schema 中应保留可区分的观察状态，建议把信号枚举扩展为 `positive/warn/negative/unknown`；否则若把“观察”存成 `neutral`，010 无法区分“中性”与“观察扣分”。
- 010 当前不是用模型重新判断茅台的维度信号；它主要消费 009 已保存的 `valuation_signal_pack`，再按确定性公式转成参数调整。
