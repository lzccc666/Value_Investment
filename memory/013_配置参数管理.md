# 013_配置参数管理

## 模块定位

013 是 004-011 研究主链路的统一参数配置中心。它集中管理会影响数据采样、财务预警、分析师判断、Memo、无锚定估值和价格决策的新运行参数，同时保持 price-blind、历史不可变性和会计基础定义等结构性约束固定在代码中。

本模块只管理参数，不属于 012 的 SQLite 运维功能。参数源码文件不随 SQLite 备份；008-011 已生成运行保存的参数快照会随数据库备份和恢复。

## 最终产品约定

- 页面名称为“参数配置”，从主侧边栏直接进入，不再显示旧的 “Global Parameters” 英文页面。
- 不区分普通参数和专家参数，七个配置域内直接展示全部可编辑的非审计参数。
- 不保留草稿、配置版本、发布历史或回滚记录。旧数据库表只为兼容保留，当前流程不读写它。
- 页面编辑只存在于浏览器内存；刷新、关闭或离开后未发布内容丢失，不留记录且不生效。
- “校验配置”只执行完整校验，不写任何文件。
- “发布并应用”在校验通过后直接覆盖唯一的源码参数 JSON；存在警告时必须二次确认，严重错误阻止发布。
- 发布不修改 Python 或 TypeScript 程序文件，只修改 `backend/app/configuration/active_parameters.json`。
- 发布后的参数只影响后续新请求和新生成运行，不追溯改写已有 008-011 结果。

## 配置域

统一配置根节点严格包含七个域：

1. `data_sampling`：公司列表、财务期数、公告同步、证据数量和文本截断。
2. `financial_flags`：CAGR、趋势稳定性和财务风险阈值。
3. `analyst_engine`：模型温度、分析师适配度、数据置信度、证据排序和等级阈值。
4. `valuation_rule_matrix`：010 专用状态分、分析师差异化权重和 40 条规则到 13 个估值维度的映射。
5. `memo_decision`：009 专用状态分、生成门槛、置信度映射和建议安全边际公式。
6. `valuation_models`：TTM/FCF、增长、折现、情景、五模型、资产折扣、置信度和敏感性。
7. `price_decision`：安全边际范围、买入参考情景和价格历史采样。

默认配置当前有 372 个实际生效数值，其中包含规则矩阵的 111 个实际维度系数。92 个旧 `parameter_impacts` 方向系数只作为内部兼容审计数据保留，不参与计算、不在前端展示，也不允许编辑。各业务字段的默认值、范围、完整公式和代码位置见 `memory/004` 至 `memory/011`。

## 存储与发布

### 参数来源

- 内置默认：`backend/app/configuration/defaults.py`，是缺少源码参数文件时的统一代码级安全默认。
- 当前源码参数：`backend/app/configuration/active_parameters.json`，存在且通过完整校验时优先使用。
- 中文元数据：`backend/app/configuration/parameter_copy.py`，集中提供中文名称和细致作用说明。

允许通过环境变量 `VALUE_INVESTMENT_PARAMETER_CONFIG_PATH` 覆盖源码参数文件位置，主要用于测试或独立部署。

### 原子发布

后端收到发布请求后先复制并完整校验配置。通过后，在目标目录写入临时文件、刷新并执行 `fsync`，最后用 `os.replace` 原子替换 `active_parameters.json`。写入失败会清理临时文件并返回错误，避免留下半份配置。

### 读取与回退

- 源码文件不存在：整套使用内置默认，`source=builtin_default`。
- 源码文件存在且有效：整套使用源码参数，`source=source_file`。
- 源码文件损坏或校验失败：整套回退内置默认，`source=builtin_fallback`，记录 `fallback_reason=source_config_invalid`。
- 禁止局部读取新配置、局部混用旧常量，以免同一次分析使用两套参数。

配置内容按稳定 JSON 序列化计算 SHA-256。每个新 008-011 运行保存 `config_hash` 和完整 `config_snapshot`；`config_version` 保持为空。历史运行始终按自己的快照解释，后来发布参数不会改变历史结果。

## API

统一前缀为 `/api/parameter-config`：

| 方法 | 路径 | 作用 | 是否写文件 |
| --- | --- | --- | --- |
| `GET` | `/current` | 当前源码参数、来源、哈希、校验结果和中文元数据 | 否 |
| `GET` | `/defaults` | 内置默认参数及元数据 | 否 |
| `POST` | `/validate` | 返回全部错误和警告 | 否 |
| `PUT` | `/current` | 校验、警告确认并原子发布 | 是 |

旧 `/versions`、`/drafts`、历史和回滚路由均不存在，应返回 404。直接打开后端根地址也不是配置页面；浏览器应访问前端地址，后端只提供 `/api` 和接口文档。

发布错误语义：

- `409`：存在警告但尚未确认。
- `422`：存在严重校验错误，响应携带完整错误列表。
- `400`：源码参数文件写入等配置服务错误。

## 后端校验

校验以整包配置为单位，至少覆盖：

- 七个根域必须精确完整，不允许缺失或多出。
- 所有数值必须有限，字段类型、上下限和枚举必须有效。
- 组合权重按各自公式合计为 1；五模型权重合计为 100%。
- 折现率至少高于永续增长率 1 个百分点。
- 保守、中性、乐观情景及资产折扣保持合理单调关系。
- 安全边际只能位于 0%-50%。
- 规则矩阵必须保持 40 条规则、38 条 `compute`、2 条 `price_reference`、13 个维度全集和 111 个实际系数。
- `price_reference` 不得进入 010 计算，`parameter_impacts` 必须保持 `audit_only`。
- price-blind、确认估值参数前禁止计算、历史不可变、会计恒等式和 TTM 基本定义不能通过配置关闭。

校验一次返回全部问题，不因第一个错误提前结束。配置相对默认值发生变化时会生成发布影响提示；警告允许确认后发布，错误永远阻止发布。

## 前端交互

参数页同时请求 current 和 defaults，以后端 metadata 为唯一名称、说明、单位、范围、风险和默认值来源。前端不再维护第二套默认参数或根据英文键猜测中文含义。

页面能力：

- 七个配置域标签页。
- 中文参数名、中文作用说明、当前值、默认值、单位和允许范围。
- 百分比按百分数编辑，提交时转换为后端小数；计数、状态分、权重指数、维度分和情景倍数保留真实单位。
- 单项恢复默认和当前分组恢复默认。
- 校验结果按中文参数名定位字段。
- 发布前显示变更摘要；错误阻断，警告要求二次确认。
- 数值显示最多按 10 位十进制归整，整数显示为整数，避免 `.9999999999` 或 `.00000000001` 浮点尾巴。

规则矩阵支持按分析师、规则和实际计算维度筛选。筛选框只保留浏览器原生下拉箭头；维度名称与输入框使用紧凑布局。手机端逐条纵向展示“分析师/规则、计算角色、实际计算维度”，不依赖横向滚动。

## 中文语义体系

中文文案由后端 `parameter_copy.py` 统一生成，前端直接展示 `metadata.label` 和 `metadata.description`。本轮逐项对照真实代码后，共核验 269 个前端可见非规则字段：中文名称唯一、作用说明唯一、未命名项为 0、通用占位说明为 0。

说明必须写清：参数控制对象、触发条件、计算公式、数值增大或减小的方向、单位、实际生效步骤和下游模块。不能只写“影响分析结果”“用于配置计算”等同质化文本。

重点歧义修正：

- `cash_flow_quality` 表示“存在经营现金流数据时的质量视角加分”，不是直接认定现金流质量良好。
- `permanent_loss_optimistic_cap` 表示达到永久损失风险阈值后停止上调乐观永续增长，不是永续增长率数值上限。
- 009 与 010 的规则状态分使用独立中文名称和说明，不能混成同一个分数。
- 稳定性振幅按真实 `max(values)-min(values)` 绝对差解释，不表述为相对振幅。
- FCF 弱现金转化阈值降低基线置信度并产生提示，不直接调整 DCF 权重。
- 未知分析师默认分只在异常未知标识时兜底，正常十位分析师配置不会触发。

111 个规则映射系数按具体分析师、规则和维度动态说明，明确公式为：

```text
规则贡献 = 010规则状态分 × 分析师差异化权重 × 维度映射系数
```

维度贡献先聚合为质量、增长和风险分，再映射到 G、OG、DR、TG、SP；系数不会直接加到最终估值参数。2 条价格参考规则明确只作 011 参考，不进入 010。

无锚定估值页“008 规则到参数审计”的 13 个维度和 5 个估值参数均显示中文；规则贡献最多显示 4 位小数并去掉尾随零，这只影响展示，不改变保存值。

## 实际生效链路修正

逐项核对时发现部分字段虽然已出现在配置页，业务路径仍有硬编码或没有读取。本轮已修正：

- 004：公司列表默认数量和单次最大数量由后端运行配置控制，前端不再固定传 20。
- 005：财务报告期默认数量由后端运行配置控制，前端不再固定传 60；分析证据包读取同一值。
- 006：公告来源单页数量和最大翻页次数接入东方财富公告客户端。
- 007：外部搜索默认数量由后端补齐，前端不再固定传 10；网页摘录、快照摘要和标题长度分别读取对应配置。
- 007：手工导入模型摘录长度与审计快照长度此前使用相反，现已分别按 `manual_import_model_chars` 和 `manual_import_snapshot_chars` 使用。
- 008：`source_priority` 进入外部证据选择分数；`profile_default_score` 作为未知分析师兜底。
- 009：`memo_list_items` 真实控制风险项和估值差距项的模型输入上限。
- 010：FCF 封顶值和弱转化提示显示当前配置值，不再显示硬编码默认值。
- 011：价格决策历史默认数量由后端配置控制，前端不再固定传 20。

## 结构性约束

以下内容有意固定在代码中，不开放配置：

- 008-010 price-blind 边界，当前价、市值、持仓成本和估值倍数不能进入分析与估值。
- 当前价格只允许在 011 进入。
- 010 必须先确认估值参数才允许计算。
- 40 条规则顺序、十位分析师顺序、规则状态枚举以及 38/2 计算角色划分。
- 009 的 40 条规则等权模式。
- 会计恒等式、TTM 基本定义、缺失数据不猜测。
- 已发布配置和历史运行快照不可原地修改。

这些约束如果开放为开关，会破坏跨模块合同、价格隔离或历史可复现性，因此只允许通过代码变更和完整回归测试调整。

## 后续维护规则

- 新增或修改参数时，同时更新集中默认值、完整校验、中文文案、实际业务读取点、对应 004-011 memory 和本文件。
- 不能只把字段加入配置页而不接入业务调用；测试至少证明修改该参数会改变预期的新请求或新运行。
- 前端不得重新引入英文键推导、独立默认值、草稿/版本存储或普通/专家分层。
- 修改规则矩阵时必须重新核验 40 条规则、13 个维度、111 个计算系数、38/2 角色划分和 price_reference 隔离。
- 视觉变更后同时检查桌面和 390px 手机视口，确保长中文说明、输入框和矩阵行不裁切、不重叠、不产生页面级横向滚动。
