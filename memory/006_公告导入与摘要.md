# 006_公告导入与摘要

## 模块目标

006 负责把公司公告稳定导入本地数据库，并为公告生成当前可展示摘要。公告导入、公告列表、来源追溯、删除、快速摘要、深度摘要和公告正文读取都统一走后端，前端不直接访问第三方公告源或模型 API。

当前公告列表只搜索并保留最近一年内最多 50 条公告。公告摘要只保存最新一次结果，不保存历史版本。

## 当前实现

### 后端

- 公告数据源：`backend/app/data_sources/eastmoney_announcements.py`
- 公告正文读取：`backend/app/data_sources/announcement_content.py`
- 公告同步服务：`backend/app/services/companies.py`
- 公告摘要服务：`backend/app/services/announcement_summary_service.py`
- 公告接口路由：`backend/app/api/routes/companies.py`

公告同步优先支持 A 股证券代码，例如 `600519.SH`、`300750.SZ`。默认读取最近一年公告，最多保留 50 条。

### 前端

公司详情页公告区块提供：

- `搜索公告`
- `一键快速摘要`
- `一键深度摘要`
- 单条 `深度摘要`
- 单条删除
- 来源链接
- 本地公告 ID、摘要、关键事实、标签和摘要状态展示

前端接口封装位于 `frontend/src/services/api.ts`，主页面位于 `frontend/src/app/CompanyWorkspaceView.tsx`。

一键深度摘要的前端待处理计数会把历史东方财富页面壳坏正文记录视为待重跑，避免显示“准备处理 0 条”但后端实际会重读正文。

## 数据保留规则

- 公告同步只保留最近一年内最多 50 条公告。
- 同步完成后删除该公司一年窗口外公告，并按发布时间倒序只保留最新 50 条。
- 重复公告按稳定 key 识别：
  - 优先 `company_id + source_url`
  - 无链接时使用 `company_id + title + published_at`
- 搜索公告时，如果公告已经存在，默认跳过，不覆盖已有摘要。
- 用户手动删除的公告会从本地库删除；如果之后第三方源仍返回该公告，再次搜索仍可能重新入库。
- 公告重要性已取消，列表不展示 `importance_score`，摘要生成会把当前 `importance_score` 置空。
- 搜索公告遇到已存在公告时默认跳过并保护已有摘要；但如果本地 `raw_content/content` 被识别为东方财富页面壳，会清空坏正文、坏摘要和摘要模型状态，重新标记为 `unprocessed`，让后续深度摘要重读真实正文。

## API

```text
GET    /api/companies/{company_id}/announcements
POST   /api/companies/{company_id}/announcements/sync?years=1
DELETE /api/companies/{company_id}/announcements/{announcement_id}
POST   /api/companies/{company_id}/announcements/summarize-all
POST   /api/companies/{company_id}/announcements/summarize-all-deep
POST   /api/companies/{company_id}/announcements/{announcement_id}/summarize
```

公告同步响应包含：

```json
{
  "company_id": 1,
  "source": "eastmoney_announcements",
  "fetched": 50,
  "created": 3,
  "updated": 0,
  "skipped": 47,
  "pruned": 2,
  "errors": [],
  "items": []
}
```

`pruned` 表示本次同步清理的一年窗口外旧公告和超过 50 条保留上限的旧公告数量。

## 正文读取

深度摘要会优先使用 `raw_content/content`。如果本地没有正文，后端会尝试读取 `raw_url/source_url`。

东方财富公告详情页 `https://data.eastmoney.com/notices/detail/{code}/{art_code}.html` 的静态 HTML 通常只是页面壳，正文由浏览器 JavaScript 再请求接口填充。因此后端现在不会只解析静态页面，而是优先根据 `AN...` 公告代码调用：

```text
https://np-cnotice-stock.eastmoney.com/api/content/ann
```

关键参数：

- `art_code`
- `client_source=web`
- `page_index`

读取规则：

- 优先读取东方财富正文接口返回的 `notice_content`。
- 如公告存在分页，按 `page_size` 读取并合并分页正文。
- 正文接口失败时，再回退到原来的 `raw_url/source_url` 读取。
- PDF 链接仍作为兜底。
- HTML 兜底优先读取 `id="notice_content"` 容器，避免把导航、广告、页面声明误当作公告正文。
- 如果历史库里的 `raw_content/content` 是东方财富详情页页面壳（例如只包含“公告正文 _ 数据中心 _ 东方财富网”“Choice数据”等导航文本），深度摘要不会继续信任该本地正文，会重新通过东方财富正文接口或兜底链路读取真正公告正文。

有些公告正文接口只返回标题或极短内容，此时深度摘要仍可能退化为元数据摘要或需要人工复核。

## 摘要规则

### 一键快速摘要

`POST /api/companies/{company_id}/announcements/summarize-all`

默认参数：

```text
limit=50
only_missing=false
include_failed=true
```

当前规则：

- 一次处理当前公告列表内最多 50 条公告。
- 跳过已经深度摘要过的公告。
- 不读取 PDF/HTML/正文接口。
- 不调用模型 API。
- 只基于标题、分类、发布时间、来源和来源链接生成关键词摘要。
- 每条公告分别写回自己的当前摘要字段。
- 不写 `analysis_runs`。
- 重新生成会覆盖当前展示摘要，不保存旧摘要版本。
- `summary_model_name` 写为 `metadata_keyword`。

### 一键深度摘要

`POST /api/companies/{company_id}/announcements/summarize-all-deep`

当前规则：

- 一次处理当前公告列表内最多 50 条公告。
- 跳过已经深度摘要过的公告；但如果已深度摘要记录的本地正文是东方财富页面壳，会重新纳入一键深度摘要列表并重读正文。
- 后端逐条复用单条深度摘要流程。
- 每条公告分别写回自己的当前摘要字段。
- 不保存历史版本。

### 单条深度摘要

`POST /api/companies/{company_id}/announcements/{announcement_id}/summarize`

当前规则：

- 优先使用有效的 `raw_content/content`；如果本地内容被识别为东方财富页面壳，则忽略本地内容并重新读取原文。
- 没有本地正文时，尝试读取东方财富正文接口、PDF 或 HTML 原文。
- 有正文时通过后端模型网关生成结构化摘要。
- 原文读取失败时退化为元数据关键词摘要。
- 不保存历史版本，只更新 `announcements` 当前字段。
- 不复用历史 messages，不使用 conversation/thread id，不读取旧 `analysis_runs`。

## 模型边界

- 前端不直接调用模型 API。
- 一键快速摘要不调用模型。
- 单条深度摘要和一键深度摘要只把当前公司、当前公告和当前公告正文传给模型。
- 模型只作为研究助理，不输出买卖建议、仓位、目标价或估值结论。
- 公告摘要不创建 `analysis_runs` 历史。
- 007 外部信息搜索和 008 分析师视角仍按各自规则使用 `analysis_runs`。

## 后续分析师证据字段

后续分析师视角读取公告作为证据时，只传递：

- `id`
- `title`
- `published_at`
- `category`
- `summary`
- `key_facts`
- `tags`

后续分析师公告选择规则：

- 从最近公告候选池中选最多 20 条公告进入分析快照。
- 已深度摘要公告优先于快速摘要或未深度摘要公告进入快照。
- 深度摘要优先级之后，再按公告类型、会计口径/治理/分红回购/重大事项信号、摘要有无和发布时间排序。

当前版本不把公告摘要复制到独立 Evidence 表。007 外部信息智能搜索负责独立 Evidence 入库。

## 当前边界

- 006 公告同步不按情绪、价格、标题或分类关键词过滤公告。
- 006 公告同步只做公告基础字段和来源追溯入库。
- 006 公告列表只保留最近一年内最多 50 条公告。
- 一键快速摘要是关键词摘要，不代表公告正文级解读。
- 深度摘要用于关键公告正文级摘要，仍只保存每条公告最新结果。
