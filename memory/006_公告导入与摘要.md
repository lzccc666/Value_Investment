# 006_公告导入与摘要

## 模块职责

006 管理公司公告的同步、正文读取和结构化摘要，为 008 提供公司官方披露证据。公告只保留当前最新摘要，不维护单独摘要版本表。

## 当前能力

- 从东方财富同步最近一年公告，单公司最多保留 50 条。
- 按来源公告 ID 去重；再次同步不会覆盖已有有效摘要。
- 识别并清理误存的东方财富页面壳内容。
- 通过 notice API 优先读取正文，失败时回退 PDF 或 HTML。
- 支持快速批量摘要、深度批量摘要和单条深度摘要。
- 支持前端搜索、同步、摘要进度、结果展示和单条删除。

## API

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| `GET` | `/api/companies/{company_id}/announcements` | 读取公告 |
| `POST` | `/api/companies/{company_id}/announcements/sync` | 同步最近一年公告 |
| `POST` | `/api/companies/{company_id}/announcements/{announcement_id}/summarize` | 单条深度摘要 |
| `POST` | `/api/companies/{company_id}/announcements/summarize-all` | 快速批量摘要 |
| `POST` | `/api/companies/{company_id}/announcements/summarize-all-deep` | 深度批量摘要 |
| `DELETE` | `/api/companies/{company_id}/announcements/{announcement_id}` | 删除公告 |

## Announcement 关键字段

- 元数据：`title`、`announcement_type`、`published_at`、`url`
- 来源：`source`、`source_announcement_id`
- 内容：`raw_content`、`content_source`、`content_fetched_at`
- 摘要：`summary`、`summary_mode`、`summary_status`、`summary_model`
- 证据：`summary_facts`、`summary_tags`、`summary_generated_at`
- 追踪：`created_at`、`updated_at`

## 摘要模式

### 快速摘要

快速批量摘要主要基于公告元数据和已知内容生成紧凑结构，不要求每条都完成模型深读。适合先清理和标记公告池。

### 深度摘要

深度摘要会先读取正文，再调用模型生成结构化摘要、事实和标签。已经存在有效深度摘要的公告会跳过；读取或模型失败会记录到批次结果，不伪造成功内容。

### 正文安全规则

- 页面标题、脚本壳或错误页不视为公告正文。
- 已保存内容被识别为页面壳时会重新抓取。
- 正文来源和抓取时间独立保存，便于判断摘要依据。

## 模型边界

- 模型必须输出符合 Pydantic schema 的结构。
- 摘要是研究线索，不替代原公告；前端始终保留来源链接和公告 ID。
- 模型未配置、超时或输出校验失败时返回明确错误。
- 公告作为官方披露，不在 007 中重复创建为普通外部证据。

## 当前限制

- PDF 扫描件、复杂表格和反爬页面的正文质量不稳定。
- 单条公告仅保存最新摘要，无法比较摘要版本。
- 一年/50 条保留策略可能遗漏更早的长期事项，需要时应扩展归档策略。
