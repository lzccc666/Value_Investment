# 011_价格对照与投资决策

## 模块职责

011 是研究主链路最后一步。它绑定一个已经完成计算的 010 估值和该估值固定关联的 009 Memo，再读取公司当前价格，生成安全边际买入价与价格状态。它不管理资金、持仓或组合。

## 输入约束

- 估值必须属于当前公司。
- `ValuationRun.results.status` 必须是 `calculated_after_user_confirmation`。
- 必须有有效的保守、中性、乐观每股内在价值，且顺序递增。
- 必须使用该估值绑定的 Memo，不回退到公司最新 Memo。
- Memo 必须包含分析师综合分和 `0%-50%` 的建议安全边际。
- 公司必须有正数当前价格和行情更新时间。
- 用户可覆盖安全边际，范围同样是 `0%-50%`，原建议值仍单独保存。

## 确定性公式

```text
scenario_buy_price = scenario_intrinsic_value * (1 - effective_safety_margin)
suggested_buy_price = base_buy_price
current_margin = 1 - current_price / base_intrinsic_value
```

`effective_safety_margin` 默认使用 009 建议值；有用户覆盖时使用覆盖值。

价格状态按以下顺序判断：

1. 当前价 `<=` 建议买入价：`达到目标安全边际`
2. 当前价 `<` 中性内在价值：`低于内在价值但安全边际不足`
3. 当前价 `<=` 乐观内在价值：`处于估值区间上半部`
4. 其余：`高于乐观内在价值`

## PriceDecisionRun

每次生成创建新版本并保存：

- 公司、估值和 Memo 绑定关系
- 三情景每股内在价值
- 当前价格与行情更新时间
- 分析师评分卡快照
- 建议、覆盖和生效安全边际
- 三情景买入价、建议买入价和当前安全边际
- 价格状态、输入快照哈希和公式版本
- `version_no`、状态和软删除时间

历史记录不可原地重算；删除将状态改为 `deleted` 并写入 `deleted_at`。

## API

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| `POST` | `/api/companies/{company_id}/price-decision-runs` | 生成价格决策 |
| `GET` | `/api/companies/{company_id}/price-decision-runs/latest` | 最新有效版本 |
| `GET` | `/api/companies/{company_id}/price-decision-runs` | 历史列表 |
| `GET` | `/api/price-decision-runs/{run_id}` | 版本详情 |
| `DELETE` | `/api/price-decision-runs/{run_id}` | 软删除 |

创建请求可传 `valuation_run_id` 和 `safety_margin_override`。未指定估值时，服务选择当前公司最新的已完成估值。

## 前端行为

- 显示绑定的估值版本、Memo 版本和行情更新时间。
- 同时展示建议安全边际与用户覆盖输入。
- 展示三情景内在价值、三情景买入价、当前安全边际和价格状态。
- 支持生成、查看历史和手工删除。
- 缺少行情、已完成估值或兼容 Memo 时显示明确的上游修复提示。

## 当前边界

- 输出是基于研究假设的价格参考，不是自动交易指令。
- 当前价格只在 011 引入，不反向污染 008-010。
- 不提供买卖数量、仓位比例、组合约束、账户余额或交易执行。

价格状态边界的比较方向用于保证无缝、互斥分区，普通配置只允许调整安全边际范围和买入参考情景，不允许改变比较符号。当前价格只能在 011 读取、估值必须绑定已确认 010 与固定 Memo、三情景必须单调、历史记录不可原地重算，均为结构性约束。

新 `PriceDecisionRun` 保存 `config_hash/config_snapshot`，`config_version` 为空，因此历史安全边际校验范围和买入参考情景仍可复现；后续发布源码参数只作用于新记录。

### 2026-08-16 实现补充

- 011 只在本阶段读取当前价，生成时绑定当次源码参数；安全边际范围和建议买入价情景来自同一快照。
- 最新结果和历史详情保留参数哈希、估值、Memo、行情更新时间和输入哈希，便于完整复现，不再依赖配置版本号。

### 2026-08-17 参数语义复核

- `price_decision_history_limit` 现在是后端历史列表请求未传 `limit` 时的真实默认条数，前端不再固定传 20；它只控制列表采样，不改变价格状态或买入参考价公式。
