# 011 价格对照与投资决策

## 职责

011 是研究链路中唯一允许读取当前价格的阶段。它绑定一条已经确认完成的 010 ValuationRun 及该估值固定关联的 Memo，读取 010 冻结的 dynamic_safety_margin，再生成买入参考价和价格状态。

011 不重新读取 008，不读取 Memo 评分，不计算分析师分数，不重算动态安全边际，也不管理资金、持仓或组合。

## 输入门槛

- ValuationRun 必须属于目标公司且状态为 completed。
- ValuationRun 必须有可用的三情景内在价值。
- ValuationRun 必须绑定有效 Memo。
- ValuationRun.results.dynamic_safety_margin 必须存在且位于 10%-50%。
- 新运行必须选择属于当前 Company 的启用 common_stock/ads Listing，并绑定正数、未过期且币种与 Listing 一致的不可变 `MarketSnapshot`。未传 `listing_id` 时使用主 Listing；仅旧兼容测试数据允许从已有 Company 冻结行情即时物化带 `legacy_company_snapshot` 来源的快照。
- 010 的估值币种、Listing 交易币种和 `underlying_shares_per_listing_unit` 必须明确。跨币种时必须绑定未过期 `FxRateSnapshot`；同币种汇率固定为 1 且不伪造 FX 外键。
- 用户覆盖值可空；非空时范围为 10%-50%。

默认选择该公司最新完成的 010，但 API 可显式指定 valuation_run_id。新 009 Memo 不会改变既有 010 的 memo_id 或既有 011。

## 安全边际

- suggested_safety_margin：直接读取绑定 010 的冻结动态安全边际。
- safety_margin_override：用户可选覆盖值。
- effective_safety_margin：有覆盖时取覆盖，否则取建议值。
- Listing 内在价值：发行人每股内在价值 × Listing 证券单位对应股数 × valuation->trading FX。
- 买入价：Listing intrinsic_value × (1 - effective_safety_margin)。

建议值、覆盖值、生效值、010 公式版本和来源快照分别保存，历史可复现。前端输入以百分比展示，允许 10%-50%。配置变化不改写既有 010 或 011；绑定的旧 010 建议值不在当前范围内时，需要重新生成 010 后再创建新的价格决策。

## 价格状态

以配置的参考情景内在价值和买入价为边界：

1. current_price <= suggested_buy_price：达到目标安全边际。
2. current_price < base_intrinsic_value：低于内在价值但安全边际不足。
3. current_price == base_intrinsic_value：接近内在价值。
4. current_price > base_intrinsic_value：高于内在价值。

三情景分别保存 intrinsic_value、buy_price 和相对当前价的安全边际。比较边界固定互斥。

## API 输出

公开 API 返回：

- valuation_run_id、memo_id、listing_id、market_snapshot_id、可空 fx_rate_snapshot_id。
- valuation_currency、trading_currency、underlying_shares_per_listing_unit、fx_rate，以及换算前后的三情景每股内在价值。
- current_price、market_data_updated_at。
- conservative/base/optimistic 内在价值与买入价。
- suggested_safety_margin、safety_margin_override、effective_safety_margin。
- reference_scenario、suggested_buy_price、current_margin_of_safety、price_status。
- 来源与配置快照元数据。

API 和前端不返回 analyst_score_total 或 analyst_scorecard。数据库中的同名旧列只为兼容已有历史表结构，允许空值；新记录不伪造 0 分。

## 历史与不可变性

每次生成创建新的 PriceDecisionRun。旧价格决策、旧价格快照、绑定估值与 Memo 均保留；配置发布、008 修改、009 重生成或新 010 都不会原地改写历史 011。

schema v5 已新增不可变 `MarketSnapshot` 和 `FxRateSnapshot`，v6 为新 FX 快照增加可空计算审计。新价格决策绑定其 Listing/行情/可选 FX 外键并冻结币种方向、比率、汇率、ECB 同日交叉换算审计和公式版本；历史记录继续读取自身冻结字段，新外键与旧审计允许为空，不回填、不重算也不伪造来源。

Apple `AAPL.US` 固定样本已验证 USD/USD 身份汇率、Listing 比率 1、MarketSnapshot 外键和 010 USD/share basis 进入 011。腾讯 `00700.HK` 固定样本已验证 CNY 估值、HKD MarketSnapshot、CNY/HKD FxRateSnapshot、比率 1 及 `issuer per share × ratio × FX` 换算。阿里巴巴同一 Company 的 `09988.HK` 普通股与 `BABA.US` ADS 已验证独立行情、CNY/HKD 与 CNY/USD、1 与 8 的证券单位比率、主 Listing 切换后旧 010/011 不变，以及缺失 ADS 比例、过期行情和缺失/过期 FX 的明确阻断。

ECB Provider 使用官方 EXR 日度 CSV，以同一 rate date 的 `quote_per_eur / base_per_eur` 构造 CNY/HKD/USD/EUR 交叉汇率。`FxRateSnapshot.calculation_audit` 冻结两个 EUR 基准值、公式和来源哈希；identity FX 固定为 1 且不持久化伪造快照。离线 fixture 与独立真实 smoke 均已通过。

## 前端

011 区域展示绑定估值、当前价格、建议安全边际、10%-50% 覆盖输入、三情景买入价、当前安全边际和价格状态。不展示分析师评分卡或综合分。
