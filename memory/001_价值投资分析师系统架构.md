# 001_价值投资分析师系统架构

## 本轮目标

在 `Value_Investment` 项目中启动一个可交互的价值投资分析工具。当前聊天框只负责系统架构、功能模块拆分和开发记录，不写具体业务功能代码。后续每个聊天框可以围绕一个模块继续实现，并在 `memory/` 目录中追加对应开发记录。

## 产品定位

构建一个面向个人投资研究的网页式交互应用，帮助用户围绕单家公司、行业或投资组合完成以下工作：

1. 查询和沉淀公司数据。
2. 从多位价值投资者的视角进行结构化分析。
3. 形成买点、卖点、仓位、风险和观察清单。
4. 持续追踪公告、财报、经营变化和投资假设是否失效。

系统应避免只给出单一结论，而是把“证据、推理、假设、反证、建议”分层展示，让用户能看见分析过程。

## 推荐技术架构

### 第一阶段建议

采用轻量但可扩展的本地 Web App：

- 前端：React + Vite + TypeScript。
- UI：Tailwind CSS 或 CSS Modules，先做清爽的研究工作台，不做营销页。
- 后端：Python FastAPI。
- 数据库：SQLite 起步，后续可迁移 PostgreSQL。
- 任务队列：先用本地同步任务或 APScheduler，后续可接 Celery/RQ。
- 数据处理：pandas、polars、pydantic。
- 图表：ECharts、Recharts 或 Plotly。
- 文档解析：PDF/HTML/Markdown 文本抽取模块。
- AI 分析层：先抽象统一接口，便于后续接 OpenAI、DeepSeek、本地模型或规则引擎。

## 核心功能模块

### 1. 公司与证券主数据模块

负责维护研究对象的基础信息。

待实现能力：

- 股票代码、公司名称、交易所、行业、市值、上市日期。
- 公司简介、主营业务、管理层、控股股东、实际控制人。
- 股票别名、曾用名、同股不同权、ADR/H股/A股等映射。
- 研究状态：未研究、观察中、重点跟踪、持仓、已放弃。
- 自定义标签：护城河、周期股、消费、科技、医药、困境反转等。

关键页面：

- 公司搜索页。
- 公司档案页。
- 自选研究池。

### 2. 数据查询与采集模块

负责公司报表、公告、会议、治理和经营数据的获取。

待实现能力：

- 财务报表：资产负债表、利润表、现金流量表。
- 关键财务指标：ROE、ROIC、毛利率、净利率、自由现金流、负债率、商誉、资本开支。
- 重要公告：定期报告、业绩预告、分红、回购、增发、并购、重大合同、诉讼、监管问询。
- 董事会与股东会：议案、投票结果、重大决策、关联交易。
- 管理层行为：高管变动、股权激励、减持增持、薪酬。
- 行业与宏观：行业增速、竞争格局、利率、通胀、汇率、商品价格。
- 新闻与舆情：可作为辅助，不作为核心证据。

数据源适配器建议：

- `FinancialStatementProvider`
- `AnnouncementProvider`
- `CorporateGovernanceProvider`
- `MarketPriceProvider`
- `IndustryDataProvider`
- `NewsProvider`

每个适配器统一输出结构化结果，并保存原始来源、下载时间、报告期和可信度。

### 3. 数据清洗与指标计算模块

负责把不同来源的数据转换为可比较、可解释的研究指标。

待实现能力：

- 报表字段标准化。
- 单季度、TTM、年度数据转换。
- 同比、环比、复合增长率计算。
- 自由现金流、所有者盈余、投入资本、经营资产等派生指标。
- 异常值检测：一次性收益、资产减值、应收异常、存货异常、经营现金流背离。
- 跨公司对比和行业分位数。

建议重点指标：

- 盈利质量：ROE、ROIC、毛利率稳定性、净利率稳定性。
- 现金质量：经营现金流/净利润、自由现金流/净利润。
- 成长质量：收入增长、利润增长、资本开支效率。
- 资产质量：应收账款、存货、商誉、固定资产周转。
- 财务安全：有息负债、现金覆盖、利息保障倍数。
- 股东回报：分红率、回购、股权稀释。

### 4. 价值分析引擎

这是系统的核心。先构建多个“分析师视角”，再做综合结论。

#### 巴菲特视角

关注：

- 长期可理解的商业模式。
- 稳定且可持续的竞争优势。
- 高 ROIC、高自由现金流、低资本消耗。
- 管理层诚信和资本配置能力。
- 安全边际和合理价格。

输出：

- 护城河评分。
- 现金流质量评分。
- 管理层资本配置评分。
- 是否属于“好公司好价格”。

#### 芒格视角

关注：

- 多学科思维模型。
- 激励机制、品牌、网络效应、规模效应。
- 避免愚蠢错误和极端风险。
- 企业文化是否鼓励长期主义。

输出：

- 商业模式反脆弱性。
- 激励机制风险。
- 认知偏差提醒。
- “不碰清单”触发项。

#### 段永平视角

关注：

- 生意模式是不是好。
- 企业文化和本分。
- 消费者心智、产品力、差异化。
- 长期自由现金流和回购分红。

输出：

- 生意好坏判断。
- 企业文化信号。
- 产品/服务竞争力。
- 长期持有舒适度。

#### 费雪视角

关注：

- 长期成长空间和市场天花板。
- 管理层质量、研发能力、销售组织和成本控制。
- 利润率的可持续性，以及成长是否依赖过高资本投入。
- 通过客户、供应商、竞争对手等侧面调研验证公司质量。

输出：

- 长期成长跑道。
- 管理层与组织能力评分。
- 研发/销售/运营质量。
- 调研问题清单。
- 增长质量与估值容忍度。

#### 林园视角

关注：

- 产品是否具备高频、刚需、复购或强心智属性。
- 是否拥有垄断性、稀缺性、定价权和渠道控制力。
- 高毛利、高净利率、高现金流和持续分红能力。
- 生意是否简单、可持续，并且与普通人的长期消费习惯相关。

输出：

- 消费属性与复购强度。
- 垄断/稀缺/提价权评分。
- 高毛利现金流质量。
- 长期持有舒适度。
- 估值容忍边界与风险提醒。

#### 李录视角

关注：

- 能力圈与深度研究。
- 企业长期内在价值。
- 管理层可信度。
- 下行风险和永久性损失。

输出：

- 研究充分度。
- 关键事实清单。
- 反方证据清单。
- 永久性损失风险。

#### 彼得林奇视角

关注：

- 公司类型：快速成长、稳定成长、周期、困境反转、资产隐蔽。
- PEG、增长持续性、故事是否简单清楚。
- 普通消费者可观察到的变化。

输出：

- 公司类型分类。
- 成长故事质量。
- 估值与增长匹配度。
- 观察指标。

#### 格雷厄姆视角

关注：

- 资产安全边际。
- 盈利稳定性。
- 低估值、低负债、分散组合。
- 防御型投资标准。

输出：

- 资产折价程度。
- 防御型股票筛查结果。
- 盈利稳定性。
- 估值安全边际。

#### 瑞达利欧视角

关注：

- 宏观周期。
- 利率、通胀、信用周期。
- 资产配置和风险平价。
- 单一公司在宏观环境中的脆弱点。

输出：

- 宏观环境适配度。
- 周期位置判断。
- 组合风险贡献。
- 仓位调节建议。

### 5. 综合投资委员会模块

把多个分析师视角合并成一个结构化结论，而不是简单平均分。

待实现能力：

- 每个视角独立给出结论、证据和置信度。
- 自动识别一致意见和分歧意见。
- 标记“必须人工复核”的关键假设。
- 生成投资备忘录。
- 输出研究结论：优质、普通、存疑、回避、需复核。
- 不在未完成价格对照前输出买入、卖出、持有、减仓或仓位动作。

综合结论建议格式：

```text
研究结论：
核心理由：
最大风险：
无锚定内在价值区间：
价格对照状态：
适合投资者类型：
建议动作：仅在价格对照与决策模块完成后生成
需要继续跟踪的信号：
```

### 6. 无锚定估值与价格对照模块

负责把公司基本面转换成内在价值区间，并在估值锁定后再与市场价格对照。该模块必须明确区分“价值估算”和“交易决策”，避免当前价格、历史价格、持仓成本等信息污染内在价值判断。

#### 6.1 无锚定内在价值估算

这一阶段只回答“这家公司大概值多少钱”，不回答“现在该不该买”。

允许输入：

- 财务报表、经营指标、现金流、资产负债表。
- 商业模式、护城河、管理层、企业文化和行业证据。
- 增长率、利润率、ROIC、资本开支、分红和回购等基本面假设。
- 公告、外部证据库、用户研究笔记和分析师视角结论。

禁止输入：

- 当前股价。
- 历史股价、K 线、涨跌幅和价格趋势。
- 当前市值、历史市值和估值分位。
- 用户持仓成本、浮盈浮亏。
- 目标价、券商评级、市场情绪和短期交易观点。

无锚定估值方法：

- DCF 估值。
- 所有者盈余估值。
- 分红折现模型。
- 剩余收益模型。
- 资产清算价值和净净股估值。
- 基于商业质量、增长质量和资本回报的合理倍数估值。
- 情景分析：乐观、中性、悲观。

输出：

- 内在价值区间：保守、中性、乐观。
- 核心估值假设。
- 对关键变量的敏感性。
- 估值置信度。
- 必须人工复核的假设。
- `price_blind=true` 的估值记录。

#### 6.2 价格感知诊断与决策

这一阶段必须在无锚定估值结果锁定后才启动。它读取当前价格和市场价格数据，用于判断安全边际、买入区间、卖出区间、持有状态和仓位建议。

允许输入：

- 已锁定的 `ValuationRun`。
- 当前价格和价格日期。
- 历史价格和历史估值分位。
- 当前 PE/PB/PS/EV/EBITDA。
- 当前市值、流动性、用户持仓和组合风险。

价格感知诊断方法：

- 当前价格相对内在价值区间的折价/溢价。
- 安全边际计算。
- 当前价格隐含增长率和反向 DCF。
- 历史估值分位。
- 当前估值与基本面质量的匹配度。

买点设计：

- 目标安全边际。
- 估值历史分位。
- 关键事件触发。
- 市场恐慌或行业错杀。
- 用户自定义价格提醒。

卖点设计：

- 投资假设失效。
- 管理层诚信破坏。
- 护城河削弱。
- 估值严重透支。
- 更优机会成本。
- 仓位过度集中。

重要约束：

- `ValuationRun` 不得保存当前价格作为估值输入。
- `PriceDecisionRun` 必须绑定某次已完成的 `ValuationRun`。
- 若重新估值，必须生成新的估值版本，不覆盖旧版本。
- 买入、卖出、持有、减仓和仓位建议只能出现在价格感知决策阶段。

### 7. 仓位管理与组合模块

负责从单股建议扩展到组合决策。

待实现能力：

- 当前持仓录入。
- 成本、收益、仓位、现金比例。
- 个股最大仓位规则。
- 行业集中度。
- 相关性与共同风险暴露。
- 风险预算。
- 分批买入和卖出计划。
- 再平衡提醒。

建议规则：

- 高确定性、低估值、低杠杆公司可更高仓位。
- 周期、困境反转、高杠杆、高估值公司限制仓位。
- 单一公司仓位建议应结合用户总资产、现金需求和风险承受能力。

### 8. 投资假设追踪模块

价值投资最怕“买入后只看价格”。该模块负责持续验证投资逻辑。

待实现能力：

- 为每家公司建立投资假设。
- 每条假设绑定验证指标。
- 定期检查财报和公告是否触发变化。
- 标记假设状态：成立、削弱、失效、待确认。
- 生成复盘记录。

示例：

```text
假设：公司拥有高端品牌定价权。
验证指标：毛利率、渠道库存、提价公告、竞品价格。
失效信号：连续两个报告期毛利率下降且销量无增长。
```

### 9. 研究笔记与知识库模块

负责沉淀用户自己的理解，而不是只依赖系统输出。

待实现能力：

- 公司研究笔记。
- 财报阅读笔记。
- 公告解读。
- 管理层访谈摘要。
- 行业框架。
- 投资大师原则库。
- 失败案例库。
- 可检索标签和全文搜索。

### 10. 分析历史与版本记录模块

每次分析完成后都必须留下可追溯历史，不覆盖旧结果。

待实现能力：

- 每次运行都生成新的 `AnalysisRun` 记录。
- 保存输入快照、提示词版本、模型版本、数据版本和输出结果。
- 支持按时间线查看同一公司的历次分析。
- 支持版本对比，看到结论是如何变化的。
- 支持用户给某次分析补充备注、复盘结论和后续观察。
- 支持从历史记录快速恢复分析上下文，避免重复劳动。

推荐原则：

- 只增不改，旧分析不可被新结果覆盖。
- 任何“重新分析”都应该生成新版本，而不是修改旧版本。
- 历史记录必须能回溯到当时使用的数据和假设。
- 用户修订和模型输出分开保存，防止混淆。

前端建议页面：

- `Analysis History`：按公司和时间查看所有分析记录。
- `Analysis Compare`：对比两次或多次分析的变化。
- `Run Detail`：展示输入、输出、证据、备注和版本信息。

### 11. 交互式前端工作台

首页不做营销页，直接进入研究工作流。

建议页面：

- `Dashboard`：研究池、持仓、待处理公告、风险提醒。
- `Company Search`：公司搜索与筛选。
- `Company Workspace`：单家公司研究工作台。
- `Financials`：报表和指标图表。
- `Announcements`：公告列表、摘要、影响评估。
- `Analyst Views`：多投资者视角分析。
- `Valuation Lab`：估值参数交互模拟。
- `Portfolio`：组合、仓位、风险暴露。
- `Memo`：自动生成投资备忘录，可人工编辑。
- `Analysis History`：历史分析记录与版本对比。
- `Settings`：数据源、模型、提醒、偏好。

单家公司工作台建议布局：

```text
顶部：公司名称、代码、当前价格、研究状态、核心标签
左侧：导航和研究任务
中部：财务图表、公告、分析结论
右侧：关键假设、风险、买卖点、待办
```

## MVP 范围

第一版不要一口气做全。建议 MVP 聚焦以下闭环：

1. 手动录入或导入一家公司。
2. 展示基础信息和财务指标。
3. 自动读取或导入公告，先完成公告列表和原文入库。
4. 通过模型智能搜索政策、行业新闻、公开披露数据等外部信息，形成证据库。

7. 支持无锚定估值参数调整，先输出内在价值区间。
8. 锁定估值后再对照当前价格，展示安全边际、买入区间和持有/卖出判断。
9. 保存研究笔记和投资假设。

## 重要设计原则

1. 证据优先：任何结论都要能追溯到数据、公告、报告或用户笔记。
2. 假设透明：不要把模型输出包装成确定事实。
3. 可反驳：每份分析必须包含反方证据和失效条件。
4. 长期主义：强调商业质量、现金流、文化和资本配置，而不是短期价格预测。
5. 人机协作：系统提供结构化研究框架，最终判断由用户确认。
6. 分析留痕：每次分析都必须保存历史版本、输入快照和模型元信息。
7. 估值-决策隔离：估算内在价值时必须排除当前价格、历史价格、持仓成本和市场观点；只有在估值锁定后，价格才能进入安全边际、买卖点和仓位决策。
8. 风险先行：投资建议必须同时给出最大风险和仓位约束。

### 架构边界更新

根据 007 和 008 的实际落地，当前系统边界需要这样理解：

- `007` 是外部基本面 Evidence 入口，默认过滤价格、行情、技术分析和短线观点，避免污染基本面证据库。
- `008` 是分析师视角引擎，只读取已经入库的数据快照，不做搜索和采集；它允许读取快照中已有的市场快照字段，用于分析师框架中的估值纪律、安全边际或价格相关事实讨论。
- `010` 无锚定估值实验室仍必须严格执行价格隔离：估值输入禁止当前价格、历史价格、市值、持仓成本、市场评级和短期交易观点。
- `011` 价格对照与投资决策必须绑定已锁定的 `ValuationRun`，所有买入、卖出、持有、减仓、仓位建议只能出现在该阶段。
- 因此，`008` 的“分析师视角可讨论价格事实”和 `010` 的“无锚定估值禁止价格输入”并不冲突；二者服务不同阶段，必须在 UI 和后端服务命名上继续保持隔离。
