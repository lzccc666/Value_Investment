# 007_外部信息智能搜索与证据库

## 模块定位

007 是 Value_Investment 项目中第一个接入模型的外部信息模块，负责把政策、监管、政府公开数据、交易所/SEC/HKEX 披露、行业供需公开数据、公司公开披露以及网络线索，转化为结构化 Evidence，供后续 008 分析师视角读取。

007 的模型用途仅限于：

- 根据公司、行业和关键词生成搜索 query。
- 判断搜索结果是否与目标公司或行业基本面相关。
- 摘要公开资料。
- 提取关键事实、影响方向、风险点和待复核问题。
- 给信息分类、重要性评分和可信度评分。
- 生成通过 Pydantic 校验的结构化 Evidence。

007 不负责：

- 财务指标计算。
- DCF/PE/PEG 等估值计算。
- 买入、卖出、持有或仓位建议。
- 替代用户最终判断。

当前模块边界：

- 005 负责财务数据。
- 006 负责公告读取与入库，公告同步本身不依赖模型。
- 007 负责外部基本面信息搜索与 Evidence 结构化。
- 008 只读取既有财务、公告、Evidence 和历史 run，不重复搜索采集。

### 搜索来源

主要文件：

- `backend/app/data_sources/web_search_provider.py`

当前默认搜索链路：

- `DuckDuckGoHtmlSearchProvider`
- `BingHtmlSearchProvider`

当前策略：

- 多个 provider 的结果会合并去重，不再因为第一个 provider 返回低质量结果而截断后续来源。
- 每个 provider 独立失败，失败信息写入搜索诊断，不直接导致整次搜索失败。
- 默认搜索重点是政策、监管、政府公开数据、行业供需、社会责任、食品安全、环保、安全生产、税务、反垄断和合规等外部基本面资料。
- `AShareCompanyDisclosureSearchProvider` 保留为可选能力和测试覆盖，但不再作为默认搜索 provider，避免 007 与 006 公告读取重复。
- 旧的官方入口页 provider 保留为可选能力，但不作为默认 Evidence 候选来源。

A 股定向披露 provider 的可选用途：

- 在后续需要定向追溯交易所披露原文时，可作为候选补充。
- 默认 007 搜索不主动拉取常规年报、季报、半年报、分红、回购、业绩预告、会议决议等公告区已有内容。
- 涉及监管函、问询函、处罚、整改、环保、安全生产、食品安全等外部约束或社会影响的披露，仍可以作为基本面线索，但需要和 006 已入库公告去重并标记复核。

不作为默认披露候选：

- 纯公告检索入口。
- 官网首页、数据入口、查询入口。
- 股票交易异常波动。
- 回购股份价格上限等价格敏感披露。
- 泛泛的会议决议公告。
- 年报、半年报、季报、财报、分红派息、利润分配、回购、业绩预告、业绩快报、股东大会、董事会/监事会会议决议、投资者关系活动记录、审计报告、会计师事务所续聘、公司章程等 005/006 已覆盖或公告区重复内容。

### 搜索筛选规则

007 当前采用“内容优先”的筛选逻辑，不按特定网站名称直接拒绝。

可以进入模型候选的内容：

- 政策驱动。
- 监管要求。
- 政府公开数据。
- 交易所/SEC/HKEX 披露中的监管、问询、处罚、整改、环保、安全生产、食品安全等外部约束事项。
- 行业供需公开数据。
- 公司公开披露中不属于常规财报/公告重复项、且能补充社会、政策、监管或行业基本面判断的内容。
- 新闻、行业文章、社区长文、百科或公司官网页面中包含可复核基本面事实、公开数据或披露线索的内容。

二手来源处理：

- 媒体、社区长文、百科、行业文章等不是原始公告、监管文件或政府数据。
- 它们可以作为线索进入模型候选，但模型必须标记 `requires_review=true`。
- `analysis_note` 必须说明需要追到原始公告、监管文件或数据源复核。
- 这类来源会影响可信度评分，但不会仅因网站名称被前置过滤。

硬过滤内容：

- 财报和公告区已有内容：年报、年度报告、半年报、半年度报告、季报、季度报告、定期报告、财报、财务报告、分红、派息、利润分配、权益分派、回购、业绩预告、业绩快报、股东大会、董事会/监事会会议决议、投资者关系活动记录、审计报告、会计师事务所续聘、公司章程等。
- 实时行情、股票实时行情、五档盘口、逐笔交易、盘口。
- 当前股价、历史股价、涨跌幅、涨停、跌停。
- 目标价、荐股、买入评级、卖出评级、增持评级、股票评级、投资评级。
- 估值分位、市盈率分位、市净率分位。
- 市场情绪、投资者情绪、社区短评、短线观点。
- 资金流向、主力资金、龙虎榜。
- K 线、均线、MACD、KDJ、RSI、技术指标、技术分析。

纯入口页处理：

- 标题或内容仅为“检索入口、官网入口、搜索入口、查询入口、数据入口、首页、公告检索入口、监管信息检索”等，不进入 Evidence。
- 如果页面本身包含具体年度报告、公告日期、监管函、处罚、公示、产量、供需、统计数据等实质事实，可以按内容进入模型候选。

### 候选排序与诊断

主要逻辑位于：

- `backend/app/services/evidence_service.py`

当前候选处理流程：

1. 模型生成 query。
2. 后端补充公司、证券代码和行业相关 query。
3. 多 provider 搜索并合并去重。
4. 本地按内容硬过滤价格、技术、短线和纯入口页。
5. 本地按基本面相关性和信息密度打分排序。
6. 最多发送 `MAX_MODEL_SEARCH_RESULTS = 10` 条候选给模型。
7. 模型结构化为 Evidence。
8. Pydantic 校验模型输出。
9. 后端二次识别 `price_sensitive` 和财报/公告重复内容；价格敏感 Evidence、财报公告重复 Evidence 不进入默认基本面 Evidence 库。
10. 成功、失败或部分成功都写入 `AnalysisRun`。

搜索诊断写入：

- `AnalysisRun.result.search_stats`
- `EvidenceSearchResponse.diagnostics`

诊断字段包括：

- `query_count`
- `provider_result_count`
- `deduped_result_count`
- `candidate_before_ranking_count`
- `sent_to_model_count`
- `model_candidate_limit`
- `filtered_out_count`
- `filtered_out_by_reason`
- `query_errors`
- `provider_stats`
- `filtered_out_by_reason.company_disclosure_duplicate` 用于统计被识别为财报、分红、回购、业绩预告、会议决议等 005/006 重复内容的候选。

前端搜索完成后会展示候选、过滤和送模数量，便于判断是搜索源问题、过滤过严、模型结构化失败，还是确实没有有效候选。

## AnalysisRun 历史记录

每次外部信息搜索都会创建新的 `AnalysisRun`。

不会覆盖旧记录。

记录字段包括：

- `company_id`
- `run_type="evidence_search"`
- `analyst_profile="evidence_search"`
- `run_version="007_v1"`
- `model_name`
- `prompt_version`
- `input_snapshot`
- `result`
- `status`
- `created_at`

状态：

- `success`
- `partial`
- `failed`

失败也会记录：

- 错误摘要。
- 错误类型。
- 已有搜索诊断。

`partial` 用于：

- 搜索候选已取得。
- 模型结构化失败或超时。
- 系统保留搜索线索，但明确标记为 `search_lead`，不伪装成模型已完成评分。

## Prompt 当前要求

Query prompt：

- 只生成公开基本面资料检索 query。
- 优先覆盖政策驱动、监管要求、政府公开数据、行业供需公开数据、社会责任、食品安全、环保、安全生产、反垄断、税务和合规事件。
- query 应包含公司名称或证券代码，也可以包含行业词、政策、监管、统计、公示、处罚、供需、产量、库存、消费、渠道等词。
- 可以补充官方域名或 `site:` 限定，但不能只生成入口页检索。
- query 应尽量指向具体外部事实材料，例如政策文件、监管处罚、公示、政府统计、产量、库存、供需、渠道、消费、环保、食品安全或社会责任数据。
- query 不围绕年报发布、季报、半年报、分红、回购、业绩预告、会议决议、投资者关系活动记录等公告区已有内容。

Evidence prompt：

- 按内容筛选，不按网站名称筛选。
- 只结构化与目标公司基本面、政策驱动、监管约束、政府公开数据、公司公开披露或行业供需数据直接相关的信息。
- 不把常规财报和公告区已有内容结构化为外部信息 Evidence，例如年报、季报、半年报、分红派息、回购、业绩预告、会议决议、投资者关系活动记录、会计师事务所续聘等。
- 公司官网、媒体、社区长文、百科或行业文章如果提供可复核基本面事实、公开数据或披露线索，可以结构化为 Evidence。
- 如果来源不是原始公告、监管文件、政府数据或交易所/SEC/HKEX 披露，但内容引用了这些原始材料，必须 `requires_review=true`，并在 `analysis_note` 中说明需要追到原始公告或数据源复核。
- 如果内容主要是报价、盘口、图形指标、资金流、社区短评、二级市场评级或短期交易观点，不生成 Evidence。
- 摘要和 key facts 优先依据网页正文摘录。
- 没有正文摘录时可依据搜索结果 title/snippet，但必须在 `analysis_note` 中说明依据不足。
- 模型输出必须只返回 JSON。

## 当前已知限制

- 通用 HTML 搜索源不稳定，DuckDuckGo/Bing 可能超时、被重置或返回低质量结果。
- A 股公司披露 provider 只是 007 的可选追溯能力，不作为默认搜索链路，不替代 006 的公告读取与入库。
- 网页正文抓取是轻量 HTML 摘录，不等于完整正文解析。
- PDF、JS 渲染页面和复杂数据表仍可能只有标题和 snippet。
- 统计局、交易所、SEC、HKEX 等更稳定的定向数据抓取仍可在后续模块继续增强。
- 二手来源可以作为线索，但不能替代原始公告、监管文件和政府公开数据的人工复核。
