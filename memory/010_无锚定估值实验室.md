# 010_无锚定估值实验室

## 模块职责

010 在不读取市场价格的前提下，用财务证据、008 估值参数矩阵和用户确认假设计算每股内在价值区间。模型可提出参数建议，最终计算由后端确定性完成。

## Price-blind 边界

- 快照禁止 `current_price`、`market_cap`、历史价格、价格目标和交易动作。
- 公司身份可以进入快照，但行情字段会被清除并记录 scrub 结果。
- 009 的动态安全边际不进入估值；旧 `valuation_signal_pack` 不作为输入。
- 008 中标为 `price_reference` 的规则只审计，不参与参数聚合。

## 当前流程

1. 创建草稿，读取财务证据包、最新成功 008 矩阵和可用 Memo 引用。
2. 生成标准化估值输入、数据缺口和模型建议参数。
3. 前端展示三情景假设与五模型权重，等待用户确认或调整。
4. 用户提交后创建新的估值运行并执行确定性计算。
5. 保存方法结果、综合区间、敏感性、置信度和来源图。

没有用户确认时，结果状态为 `needs_user_confirmation`；完成计算后为 `calculated_after_user_confirmation`。数据库记录的外层 `status` 可以继续是 `draft`，011 以结果状态判断是否可用。

## 财务基准口径

- 优先识别完整年度、累计中报和单季数据。
- 利润、自由现金流、所有者盈余和分红在最新期为中期时尝试构造 TTM。
- 自由现金流可使用 TTM，或最近 3 个完整年度按 `50% / 30% / 20%` 加权；历史不足时使用可用年度并降低置信度。
- 所有者盈余使用净利润、折旧摊销、资本开支和营运资本变动的标准化组合。
- 无法可靠年度化的输入会使对应方法跳过，而不是直接把中期值当全年。

## 分析师参数聚合

- 010 每次创建草稿时重新读取最新 008 规则和矩阵。
- 分析师原始权重只由数据置信度和 Profile 适配度决定，再归一化。
- 规则状态、方向、强度和 gate 决定各估值维度对基础参数的影响。
- 高严重度数据缺口降低置信度，并保留可复核说明。

## 五种估值模型

| 模型 | 默认权重 | 核心输入 |
| --- | ---: | --- |
| 所有者盈余 | 35% | 标准化所有者盈余、增长、折现率、终值 |
| DCF | 35% | 标准化自由现金流、增长、折现率、终值 |
| 剩余收益 | 15% | 账面权益、净利润/ROE、权益成本 |
| 分红折现 | 10% | TTM/年度化分红、增长、权益成本 |
| 资产价值 | 5% | 现金、债务、权益及非现金资产折扣 |

权重必须合计 100%。用户可在确认前调整；缺少输入而跳过的方法不参与最终结果，可用方法按配置权重重新归一化。

每个方法输出保守、中性、乐观三情景的总权益价值和每股价值。综合结果保存模型加权过程、方法离散度警告和每股内在价值区间。

## ValuationRun

保存：

- 输入快照及哈希、price-blind 审计
- 标准化财务输入和来源图
- 模型建议、用户调整和最终假设
- 方法配置、五模型结果和综合区间
- 敏感性分析、置信度和数据缺口
- 来源 Memo、运行版本和用户备注

重算创建新记录并引用来源运行，不原地覆盖旧估值。

## 当前限制

- 维持性资本开支、严格投入资本、回购和行业专用估值输入仍不完整。
- 银行、保险等金融公司不一定适合通用 DCF/所有者盈余口径。
- 模型建议参数只提供研究起点，用户仍需检查增长、折现率和终值假设。
- 方法数量不会自动提高准确性；数据缺口和模型适用性会在结果中显式保留。

## 40 个分析师指标影响估值参数的完整公式

本节记录当前代码的真实计算口径。40 条规则中有 38 条进入无锚定估值计算；巴菲特的 `margin_of_safety` 和格雷厄姆的 `valuation_discipline` 仅作价格参考，对 010 估值参数的数值影响为 `0`。

### 变量与中文含义

13 个估值维度：

| 缩写 | 代码字段 | 中文含义 |
| --- | --- | --- |
| `BQ` | `business_quality` | 生意质量 |
| `MD` | `moat_durability` | 护城河持久性 |
| `GR` | `growth_runway` | 成长空间 |
| `PP` | `pricing_power` | 定价权 |
| `CFR` | `cash_flow_reliability` | 现金流可靠性 |
| `CI` | `capital_intensity` | 资本效率；正值表示资本负担可控，负值表示资本密集惩罚 |
| `BSR` | `balance_sheet_risk` | 资产负债安全性；正值表示风险检查通过，负值表示资产负债风险 |
| `MQ` | `management_quality` | 管理层质量 |

| `DD` | `demand_durability` | 需求持久性 |
| `EQ` | `execution_quality` | 执行质量 |

估值参数缩写：

| 缩写 | 代码字段 | 中文含义 | 当前使用模型 |
| --- | --- | --- | --- |
| `G` | `cash_flow_growth_rate` | 自由现金流增长率 | DCF |
| `OG` | `owner_earnings_growth_rate` | 所有者盈余/股权收益增长率 | 所有者盈余、剩余收益、分红折现 |
| `DR` | `discount_rate` | 折现率/权益资本成本 | DCF、所有者盈余、剩余收益、分红折现 |
| `TG` | `terminal_growth_rate` | 永续增长率 | DCF、所有者盈余、剩余收益、分红折现 |
| `SP` | `scenario_spread` | 保守、中性、乐观三情景宽度 | 前四种现金流/收益模型 |

资产价值模型当前只使用现金、总资产、总负债和固定资产折扣，不读取上述分析师参数。分析师规则也不改变五模型权重。

### 第一步：规则状态分

```text
通过 pass      = +1.00
观察 warn      = -0.35
不通过 fail    = -2.00
未知 unknown   =  0.00
```

中文解释：通过产生正贡献；观察产生轻度负贡献；不通过产生强负贡献；未知不直接改变维度分，但会提高未知比例并扩大情景宽度。

### 第二步：分析师权重

对第 `i` 位分析师：

```text
confidence_i = clamp(data_confidence_i, 0.20, 1.00)
fit_i        = clamp(profile_fit_score_i, 0.20, 1.00)

raw_weight_i =
  0.50 * confidence_i
  + 0.50 * fit_i

analyst_weight_i =
  raw_weight_i ^ 2
  / sum(raw_weight_all ^ 2)
```

中文解释：数据置信度和该分析框架对公司的适配度五五开；平方用于拉开高质量分析师与低质量分析师之间的权重差异，最终所有分析师权重合计为 `1`。

### 第三步：单条规则进入维度

只有 `calculation_role="compute"`、`price_blind_compatible=true` 且不是未知状态的规则进入维度计算：

```text
rule_contribution_i,r,d =
  status_score_i,r
  * dimension_mapping_weight_r,d
  * analyst_weight_i
```

某一维度 `d` 的最终得分：

```text
dimension_score_d = clamp(
  sum(rule_contribution_i,r,d)
  / sum(analyst_weight_i * abs(dimension_mapping_weight_r,d)),
  -2.0,
  +1.0
)
```

分母只包含实际进入计算的非未知规则。若某维度没有可用规则，则该维度为 `0`。

风险类维度也使用同一方向：风险检查通过时维度为正，不产生风险惩罚；观察或不通过时维度转负，随后通过 `negative(x)=max(0,-x)` 转成风险惩罚。

### 第四步：分歧、未知和数据缺口

```text
dimension_disagreement_d =
  weighted_std(
    status_score_i,r * dimension_mapping_weight_r,d,
    analyst_weight_i
  )

disagreement_avg =
  sum(dimension_disagreement_all_13_dimensions) / 13

unknown_ratio =
  unknown_compute_rule_count / all_compute_rule_count

data_gap_penalty = clamp(
  0.25 * high_gap_count
  + 0.12 * medium_gap_count
  + 0.05 * low_gap_count,
  0,
  1
)
```

中文解释：分析师之间越不一致、未知规则越多，保守和乐观情景之间的距离越大。数据缺口不是分析师指标，但会进入风险分。

### 第五步：13 个维度合成为质量、成长和风险分

```text
negative(x) = max(0, -x)

quality_score =
  0.30 * BQ
  + 0.25 * MD
  + 0.20 * CFR
  + 0.15 * MQ
  + 0.10 * PP

growth_score =
  0.40 * GR
  + 0.25 * PP
  + 0.20 * DD
  + 0.15 * EQ
  - 0.15 * negative(CI)

risk_score =
  0.25 * negative(BSR)
  + 0.25 * negative(PLR)
  + 0.20 * negative(CY)
  + 0.15 * negative(AQ)
  + 0.15 * data_gap_penalty
```

中文解释：质量分主要体现好生意、护城河、现金流和管理层；成长分主要体现成长空间、定价权、需求和执行；风险分只提取风险维度的负值，风险检查通过不会反向制造额外奖励。

### 第六步：综合分转为估值参数调整

当前分析师影响放大系数为 `1.50`。公式使用小数，例如 `0.030` 表示 `3` 个百分点乘以综合分：

```text
delta_G = 1.50 * (
  0.030 * growth_score
  + 0.012 * quality_score
  - 0.020 * risk_score
)

delta_OG = 1.50 * (
  0.020 * growth_score
  + 0.018 * quality_score
  - 0.025 * negative(CI)
  - 0.018 * risk_score
)

delta_DR = 1.50 * (
  -0.018 * quality_score
  + 0.030 * risk_score
  + 0.012 * disagreement_avg
)

delta_TG = 1.50 * (
  0.012 * MD
  + 0.006 * PP
  - 0.014 * risk_score
)

SP = clamp(
  0.020
  + 1.50 * (
      0.020 * risk_score
      + 0.012 * disagreement_avg
      + 0.012 * unknown_ratio
    ),
  0.015,
  0.080
)
```

中文解释：成长和质量提高增长率；风险压低增长率并提高折现率；质量降低折现率；护城河和定价权提高永续增长率；风险、分歧和未知扩大三情景区间。

### 第七步：叠加财务基准并生成三情景

```text
financial_growth = 第一个可用值：
  FCF CAGR 5年
  -> FCF CAGR 3年
  -> 净利润 CAGR 5年
  -> 净利润 CAGR 3年
  -> 收入 CAGR 5年
  -> 收入 CAGR 3年
  -> 默认 4%

financial_growth = clamp(financial_growth, -5%, 12%)

financial_discount = clamp(
  9.5%
  + min(2.5%, 0.5% * financial_flag_count + 0.3% * input_gap_count),
  8%,
  14%
)

G_base  = clamp(financial_growth + delta_G,  -8%, 16%)
OG_base = clamp(financial_growth + delta_OG, -8%, 15%)
DR_base = clamp(financial_discount + delta_DR, 7.5%, 16%)
TG_base = min(
  DR_base - 1%,
  clamp(2% + delta_TG, 0%, 3.5%)
)
```

```text
保守：
  G  = clamp(G_base  - SP, -10%, 10%)
  OG = clamp(OG_base - SP, -10%, 10%)
  DR = clamp(DR_base + 0.60 * SP, 9%, 18%)
  TG = clamp(TG_base - 0.30 * SP, 0%, 3.5%)

中性：
  G  = G_base
  OG = OG_base
  DR = DR_base
  TG = TG_base

乐观：
  G  = clamp(G_base  + SP, -2%, 18%)
  OG = clamp(OG_base + SP, -2%, 16%)
  DR = clamp(DR_base - 0.35 * SP, 7.5%, 14%)
  TG = clamp(TG_base + 0.25 * SP, 0%, 3.5%)
```

当 `negative(PLR) > 0.50` 时，乐观情景的永续增长率不得高于中性情景。

### `parameter_impacts` 的真实作用

每条规则还保存一组参数方向审计权重：

```text
parameter_audit_contribution_i,r,p =
  status_score_i,r
  * parameter_mapping_weight_r,p
  * analyst_weight_i
```

例如折现率映射为 `-0.4` 时：通过会产生负方向审计，表示倾向降低折现率；不通过的状态分为 `-2`，两者相乘后转为正方向，表示倾向提高折现率。

重要：这些值属于早期方向解释层，当前代码不把它们累加到 `G/OG/DR/TG/SP`。现行最终参数只使用“规则 → 13 维度 → 综合分 → 参数调整”公式；如果再叠加方向审计值，同一条规则会被计算两次。因此配置页不再展示或允许修改该列。

### 对五种模型的最终传导

```text
38 条 compute 规则
  -> 13 个维度
  -> quality_score / growth_score / risk_score
  -> G / OG / DR / TG / SP
  -> 保守 / 中性 / 乐观参数
```

- DCF 使用 `G + DR + TG`。
- 所有者盈余使用 `OG + DR + TG`。
- 剩余收益使用 `OG + DR + TG`，其中 `DR` 作为权益资本成本。
- 分红折现使用 `OG + DR + TG`。
- `SP` 决定上述四个模型的三情景距离。
- 资产价值使用固定资产折扣，不受 40 条分析师规则影响。
- 五模型权重 `35%/35%/15%/10%/5%` 也不受分析师规则影响，只能由用户确认修改。

### 文档校验

- `RULE_VALUATION_MAPPINGS` 当前覆盖 `10 × 4 = 40` 条规则。
- 其中 `38` 条为 `compute`，`2` 条为 `price_reference`。
- 本节公式对应 `backend/app/analysis/valuation_parameter_matrix.py`、`backend/app/analysis/analyst_weights.py` 和 `backend/app/services/valuation_service.py` 当前实现。
