# 010_无锚定估值实验室

## 本轮目标

本文件开始规划 `010_无锚定估值实验室`。当前先给出一版架构方案，不直接实现业务代码。

本方案已阅读并承接：

- `001_价值投资分析师系统架构.md`
- `005_公司详情财务.md`
- `008_分析师视角引擎.md`
- `009_综合投资备忘录.md`

## 模块定位

010 回答：“在不看当前价格、不看历史价格、不看持仓成本、不看市场评级的情况下，这家公司基于基本面大概值多少钱？”

010 不回答：

- 当前价格是否便宜。
- 是否买入、卖出、持有、减仓或加仓。
- 建议仓位是多少。
- 目标价是否达到或何时达到。

这些动作继续留给 `011_价格对照与投资决策`。

## 核心原则

1. 价格隔离  
   `price_blind=true` 是 010 的硬约束。输入快照不得包含当前价格、历史价格、市值、历史估值分位、持仓成本、券商评级和市场情绪。

2. 计算优先  
   估值公式、情景计算、敏感性表应由服务层确定性计算。模型可以辅助解释假设、组织文本和提示风险，但不能替代公式计算。

3. 假设透明  
   每个核心假设都必须说明来源、范围、置信度和是否需要人工复核。

4. 多方法交叉验证  
   MVP 至少支持 DCF、所有者盈余、剩余收益、分红折现和资产价值中的若干种；不同公司类型选择不同主方法。

5. 版本化  
   每次生成估值、每次用户改参数并保存，都创建新的 `ValuationRun`，不覆盖旧版本。

6. 锁定后再对照价格  
   010 估值结果只有锁定后才能进入 011。011 读取锁定估值，再引入价格做安全边际和动作判断。

## 009 如何服务 010

009 是 010 的“假设整理层”，不是估值计算层。

009 应提供：

- `valuation_assumption_queue`：从多位分析师视角合并出的估值假设队列。
- `source_map`：所有关键假设的来源 run、公告、外部证据和财务期间。
- `key_risks`：需要转成保守情景或敏感性测试的风险。
- `counter_evidence`：需要压低增长、利润率、ROIC 或终值假设的反方证据。
- `data_gaps`：010 的估值输入缺口。
- `follow_up_questions`：估值前需要人工确认的问题。
- `research_conclusion` 与 `confidence_summary`：用于估值置信度和方法选择，不用于交易动作。

010 使用 009 的方式：

- 共识观点进入基础情景候选。
- 乐观但证据不足的观点只能进入乐观情景或待复核假设。
- 关键风险进入保守情景和敏感性测试。
- 数据缺口进入 `valuation_input_gaps`，必要时阻止锁定估值。
- 反方证据进入 `risk_adjustments`，避免只按顺风假设估值。

## 输入来源

允许输入：

- 005 的 `financial_evidence_pack`。
- 009 最新或指定版本 `InvestmentMemo` 中的 `valuation_assumption_queue`。
- 009 的 `source_map`、`key_risks`、`counter_evidence`、`data_gaps`。
- 用户在 010 页面手工录入或调整的估值参数。

禁止输入：

- `Company.current_price`
- `Company.market_cap`
- 历史价格、K 线、涨跌幅
- 当前 PE/PB/PS/EV/EBITDA
- 历史估值分位
- 用户持仓成本、浮盈浮亏
- 券商目标价、评级和市场情绪

如果上游 008 或 009 文本中出现价格相关内容，010 的快照构建层必须剔除，不能进入 `valuation_inputs`。

## 2026-08-15 贵州茅台 #10 估值口径问题与优化方案

用户指出贵州茅台 `ValuationRun #10` 中：

```text
收入基准 = 922.78 亿元
净利润基准 = 445.17 亿元
自由现金流基准 = 1070.16 亿元
数据期间 = 2026 中报
```

存在明显疑问：为何自由现金流基准大于收入基准，是否说明收入/净利润/FCF 基准有问题。

复核结论：用户判断有道理。#10 的主要问题不是 DCF 公式错误，而是估值输入的期间口径不一致：

- `base_revenue` 与 `base_net_profit` 当前取的是最新期 `2026 中报`。
- `base_free_cash_flow` 当前取的是 `ttm_adjusted` 后的正常化 FCF。
- 前端展示时把中报收入/净利润和 TTM FCF 放在同一组“估值输入”里，造成 FCF 大于收入的表观异常。
- 所有者盈余模型当前使用 `2026 中报`净利润减中报资本开支，导致 owner earnings 基数只有约 `436.85 亿元`，而 DCF 基数为 `1070.16 亿元`，模型基准严重不一致。

实际 TTM 口径应统一为：

```text
TTM revenue =
  2025A revenue + 2026H1 revenue - 2025H1 revenue

TTM net_profit =
  2025A net_profit + 2026H1 net_profit - 2025H1 net_profit

TTM FCF =
  2025A FCF + 2026H1 FCF - 2025H1 FCF
```

按 #10 数据：

```text
TTM revenue ≈ 1732.38 亿元
TTM net_profit ≈ 814.34 亿元
TTM FCF before cap ≈ 1167.30 亿元
```

因此“FCF 大于收入”主要是因为拿 TTM FCF 对比了 H1 revenue；若与 TTM revenue 对比，则不是 FCF 大于收入。但 TTM FCF/TTM net profit 仍明显偏高，需要正常化。

优化方案一：统一估值基准口径

```text
valuation_base_period_type =
  ttm if latest period is interim and same-period prior year data is available
  latest_annual if no TTM can be built
  user_confirmed if user manually confirms normalized base
```

所有基准字段必须统一到同一期间：

```text
base_revenue = normalized_revenue
base_net_profit = normalized_net_profit
base_free_cash_flow = normalized_free_cash_flow
base_capex = normalized_capex
owner_earnings_base = normalized_owner_earnings
```

前端必须显示：

```text
收入基准口径：TTM / 年度 / 用户确认
净利润基准口径：TTM / 年度 / 用户确认
FCF 基准口径：TTM adjusted / 多年加权 / 用户确认
```

优化方案二：FCF 基数从单一 TTM cap 改为多候选融合

如果 `TTM FCF / TTM net profit > 1.30` 或现金流波动明显，不应只使用 capped TTM FCF，而应融合多年正常化结果：

```text
ttm_fcf_capped =
  min(ttm_fcf, 1.30 * ttm_net_profit)

weighted_annual_fcf_3y =
  0.50 * latest_annual_fcf
  + 0.30 * previous_annual_fcf
  + 0.20 * third_annual_fcf

median_annual_fcf_5y =
  median(last_5_annual_fcf)

normalized_fcf =
  0.40 * ttm_fcf_capped
  + 0.40 * weighted_annual_fcf_3y
  + 0.20 * median_annual_fcf_5y
```

这比当前单一 TTM cap 更稳，尤其适合白酒这类合同负债/预收款和营运资本波动较大的公司。

优化方案三：所有者盈余基数正常化

当前 owner earnings 基数被中报口径压低。应改为：

```text
owner_earnings_base =
  normalized_net_profit
  + normalized_depreciation_and_amortization
  - maintenance_capex
  - normalized_working_capital_need
```

对白酒龙头，不能机械扣除单期营运资本大幅正变动，应使用多年均值或用户确认的正常营运资本需求：

```text
normalized_working_capital_need =
  median_or_weighted_average(last_3_to_5y_positive_working_capital_need)
```

若无法稳定估计，则先采用：

```text
owner_earnings_base =
  normalized_net_profit
  + normalized_DA
  - maintenance_capex
```

并把营运资本作为风险调整项，而不是直接把中报 working capital change 全额扣除。

优化方案四：分析师信号需与硬财务质量互相校准

#10 中分析师信号虽然总体评价好，但最终参数仍偏低，原因包括：

- `business_quality_signal = 0.2076` 明显低于茅台实际商业质量。
- `balance_sheet_risk_signal = 0.0990` 没有充分体现净现金和极低有息负债。
- `capital_intensity_signal = -1.7980` 对“未来产能/资本开支未明”的惩罚过重，与当前资本开支/收入仅约 0.9% 不匹配。
- `cyclicality_signal = -2.0` 对白酒周期/渠道风险惩罚过重，应更多扩大情景区间，而不是像永久损失风险一样大幅抬高折现率。

建议增加财务质量 floor：

```text
if gross_margin > 0.75 and net_margin > 0.35:
  business_quality = max(business_quality, 0.75)

if net_cash > 0 and interest_bearing_debt / cash < 0.10:
  balance_sheet_risk = max(balance_sheet_risk, 0.85)

if capex_to_revenue < 0.05 and no confirmed heavy_capex_cycle:
  capital_intensity = max(capital_intensity, 0.30)

if median_fcf_to_net_profit_5y > 0.80:
  cash_flow_reliability = max(cash_flow_reliability, 0.70)
```

同时拆分风险：

```text
cyclicality_negative:
  mainly widens scenario_spread and lowers near-term growth

permanent_loss_risk_negative:
  raises discount_rate and can cap optimistic terminal growth
```

优化方案五：高质量消费龙头的折现率公式应减少过度惩罚

当前 #10 的中性折现率为 `12.74%`，对茅台这类净现金、高利润率、高品牌壁垒、现金流强的公司偏高。建议：

```text
discount_rate =
  discount_base
  - 0.018 * quality_score_positive
  - 0.008 * balance_sheet_strength
  + 0.015 * permanent_loss_risk_negative
  + 0.006 * cyclicality_negative
  + 0.006 * accounting_uncertainty
  + 0.004 * data_gap_penalty
  + 0.005 * disagreement_avg
```

对于茅台，周期性和渠道风险可以提高情景宽度，但不应把中性折现率推到接近 13%。

总体判断：

- #10 不是公式算错，而是估值基准期间不统一、所有者盈余基数偏低、分析师好评未充分转化为质量 floor 和折现率下调。
- 优先级最高的修复应是：统一 TTM/年度基准口径，再优化 FCF 和 owner earnings 正常化，然后再调分析师信号与财务质量 floor。

## 2026-08-15 DCF 基数计算细则

DCF 的 `base_free_cash_flow` 不再等同于最新一期 `free_cash_flow`。010 应新增一个明确的 `normalized_free_cash_flow` 派生过程，并把其结果作为 DCF 基数。

### 1. 期间识别

先对财务期间分类：

```text
period_type =
  annual      if period endswith "A" or report_date is 12-31 or report_type is annual
  half_year   if period contains H1 / 中报 / 半年度 or report_date is 06-30
  quarter     if period contains Q1 / Q3 / 季报 or report_date is 03-31 / 09-30
  unknown     otherwise
```

处理规则：

```text

  latest_free_cash_flow_is_dcf_base = false
  latest_free_cash_flow_role = "trend_signal_or_ttm_component_only"
```

### 2. 候选基数优先级

DCF 基数按以下优先级选择：

```text
normalized_free_cash_flow =
  priority(
    user_confirmed_normalized_fcf,
    analyst_confirmed_normalized_fcf,
    adjusted_ttm_fcf,
    weighted_annual_fcf_3y,
    median_annual_fcf_5y,
    latest_annual_fcf_adjusted
  )
```

含义：

- `user_confirmed_normalized_fcf`：用户在前端确认或手动输入的正常化 FCF，最高优先级。
- `analyst_confirmed_normalized_fcf`：009 `valuation_signal_pack` 或估值输入队列中明确给出的正常化现金流建议。
- `adjusted_ttm_fcf`：最近四个季度或最近年度加后续中报调整得到的 TTM FCF，剔除异常营运资本释放和一次性项目。
- `weighted_annual_fcf_3y`：最近 3 个完整年度 FCF 加权平均，建议权重 `[0.50, 0.30, 0.20]`，最近年度权重最高。
- `median_annual_fcf_5y`：最近 5 个完整年度 FCF 中位数，用于平滑异常年度。
- `latest_annual_fcf_adjusted`：最近完整年度 FCF，剔除已识别异常项后使用；这是最低可接受自动候选。

### 3. 年度 FCF 正常化公式

```text
raw_fcf_y =
  operating_cash_flow_y - capital_expenditure_y

adjusted_fcf_y =
  raw_fcf_y
  - non_recurring_working_capital_release_y
  - one_off_cash_inflow_y
  - accounting_policy_adjustment_y
  + one_off_cash_outflow_y
```

如果暂时无法拆出异常项：

```text
adjusted_fcf_y = raw_fcf_y
normalization_confidence -= uncertainty_penalty
scenario_spread += uncertainty_spread
```

### 4. TTM FCF 公式

若能取得最近完整年度和下一期中报：

```text
ttm_fcf =
  latest_annual_fcf
  + current_interim_fcf
  - prior_year_same_interim_fcf
```

若只有当前中报或单季，没有去年同期可比：

```text
ttm_fcf = null
valuation_input_gap = {
  field: "ttm_free_cash_flow",
  severity: "medium",
  reason: "缺少去年同期现金流，无法构造 TTM FCF；单期现金流只作趋势信号。"
}
```

### 5. 多期候选选择

```text

  0.50 * adjusted_fcf_latest_annual
  + 0.30 * adjusted_fcf_previous_annual
  + 0.20 * adjusted_fcf_third_annual
```

```text

  median(adjusted_fcf_last_5_annual_years)
```

```text

  auto_normalized_fcf = adjusted_ttm_fcf

  auto_normalized_fcf = weighted_annual_fcf_3y
elif median_annual_fcf_5y is available:

else:
```

### 6. 与净利润交叉校验

为避免 FCF 被营运资本一次性扭曲，应使用净利润交叉校验：

当综合投资备忘录给出“高端白酒龙头、品牌壁垒强、盈利现金含量极高、资产负债表稳健、股东回报积极，但利润连续下滑、会计政策变更、外部证据不足、现金流波动、回购金额缺失”等结论时，010 不应直接把文字结论当成最终估值，而应把它拆成参数影响项，先展示给用户确认，再进入计算。

正向信号映射：

- 品牌壁垒强、酱香鼻祖、高端白酒龙头：business_quality、moat_durability、pricing_power 为 positive，提高质量分，允许较高但受上限约束的永续增长率，降低部分折现率，并提高 DCF/owner earnings 方法权重。
- 毛利率、净利率高，经营现金流/净利润和自由现金流/净利润高：cash_flow_reliability 为 positive，但若备忘录同时提示现金流波动或营运资本释放，则置信度降为 medium，基准自由现金流必须使用正常化口径，不能直接年化 2026H1。
- 净现金高、有息负债极低：balance_sheet_risk 为 positive，降低财务风险溢价，并在 DCF 股权价值桥中加入净现金。
- 分红和注销式回购：management_capital_allocation 可为 positive/review；若回购金额缺失，则不能直接把回购计入每股价值增厚，只能降低置信度或进入用户确认项。

负向信号映射：

- 2026 中报和 2025 年报净利润连续同比下滑：growth_runway 为 negative/warn，降低显性期自由现金流增长率和 owner earnings 增长率，压低乐观情景上限。
- 会计政策变更与追溯调整：accounting_or_capex_uncertainty 上升，降低 owner earnings 权重、提高折现率风险溢价、扩大情景区间；未复核前不得高置信进入计算。
- 外部证据不足：data_gap_penalty 上升，所有分析师信号的 data_confidence 下调，扩大情景 spread，并触发用户确认。
- 经营现金流波动极大：cash_flow_normalization 必须进入估值输入队列，base_fcf 使用多期中枢或剔除营运资本释放后的 adjusted_fcf。
- 新增产能和未来 capex 不明：capital_intensity 为 warn，降低 FCF conversion 或 owner earnings growth，并扩大下行情景。

建议参数影响公式：

```text
base_fcf = normalized_fcf
  = median_or_weighted_average(recent_3_to_5y_fcf, ttm_fcf)
  adjusted_for(working_capital_release, one_off_items, accounting_policy_change)

growth_penalty =
  profit_decline_penalty
  + cash_flow_normalization_penalty
  + capex_capacity_penalty
  + accounting_uncertainty_penalty

quality_bonus =
  brand_moat_bonus
  + pricing_power_bonus
  + cash_conversion_bonus
  + balance_sheet_bonus

g_fcf_suggested =
  clamp(g_fcf_base + 0.010 * quality_score - growth_penalty,
        conservative_floor,
        optimistic_cap)

g_owner_suggested =
  clamp(g_owner_base + 0.010 * quality_score
        + 0.005 * management_capital_allocation_score
        - growth_penalty
        - capex_capacity_penalty,
        conservative_floor,
        optimistic_cap)

discount_rate_suggested =
  clamp(discount_base
        - quality_bonus
        - balance_sheet_bonus
        + accounting_uncertainty_penalty
        + external_evidence_penalty
        + profit_decline_risk_penalty
        + disagreement_penalty,
        0.075,
        0.160)

terminal_growth_suggested =
  min(discount_rate_suggested - 0.010,
      clamp(terminal_base
            + moat_durability_bonus
            + pricing_power_bonus
            - profit_decline_penalty
            - accounting_uncertainty_penalty,
            0.000,
            0.035))

scenario_spread =
  base_spread
  + profit_decline_spread
  + accounting_uncertainty_spread
  + external_evidence_spread
  + cash_flow_volatility_spread
  + analyst_disagreement_spread
```

在该类 memo 下，模型倾向不是“因为品牌强就提高估值”，而是：

- 基准现金流采用正常化 FCF，不采用异常高现金流的线性外推。
- 折现率可因品牌、现金流质量和净现金略降，但会被利润下滑、会计变更、证据不足重新抬高，净影响通常为小幅下降、持平或小幅上升。
- 显性增长率因利润连续下滑被下修，除非用户确认下滑是短期、非趋势性因素。
- 永续增长率可因品牌和定价权获得上限附近的候选值，但受利润下滑与会计不确定性约束，不能无条件取高。
- DCF 与 owner earnings 可作为主模型；股利模型只能作为补充或待确认模型；资产法通常为低权重安全边际参考。
- 严重度为阻止的问题，如关键会计影响金额无法确认、核心现金流无法正常化、永久损失风险高，应阻止最终计算；低严重度缺口允许计算但降低置信度、扩大情景区间。

MVP 可以先只新增 `ValuationRun`，暂不拆出假设表。后续如果要支持参数逐项审计，再增加 `valuation_assumptions` 表。

## 估值方法

MVP 建议先实现三层：

1. 基础计算层
   - DCF：基于自由现金流。
   - 所有者盈余：基于净利润、折旧摊销、资本开支和营运资本调整。
   - 剩余收益：基于股东权益、ROE 和权益资本成本。
   - 分红折现：适合稳定分红公司。
   - 资产价值：适合资产重、金融、困境或清算视角。

2. 情景层
   - 保守、中性、乐观三档。

3. 敏感性层
   - 增长率 x 折现率。
   - 终值增长率 x 折现率。
   - 利润率 x 收入增长。
   - ROE x 权益资本成本。

## 2026-08-15 估值方案确认

用户本轮确认：

- 010 只读取 009 最新未删除 memo，不提供历史 memo 选择。
- 输出同时给 `total_equity_value` 和 `per_share_value`；如果缺少总股本，仍给总股权价值，并把每股口径标记为 `needs_input`。
- 折现率、永续增长率和情景参数应在前端以可修改参数形式呈现。
- 严重度高的输入缺口阻止锁定估值；低严重度缺口允许锁定，但降低置信度。

估值方案采用“主模型 + 交叉验证 + 适用性选择”：

1. DCF 自由现金流折现
   - 作为非金融、现金流可解释公司的主模型。
   - 输入：`base_free_cash_flow`、阶段增长率、折现率、永续增长率、现金、有息负债、总股本。
   - 若缺少严格自由现金流但有经营现金流代理口径，MVP 可以生成 `needs_review` 结果，不直接锁定高置信估值。

2. 所有者盈余估值
   - 作为价值投资主视角的第二主模型，用于和 DCF 交叉验证。
   - 输入：净利润、折旧摊销、资本开支、营运资本变化、一次性项目调整。
   - 当前若折旧摊销或营运资本变化缺失，可先用可解释简化口径，并降低置信度；严重缺口阻止锁定。

3. 剩余收益模型
   - 作为资产负债表和 ROE 更稳定公司的补充模型。
   - 输入：股东权益、ROE、权益资本成本、留存收益假设。
   - MVP 可先保留 schema 和 `skipped/needs_input`，第二轮实现完整计算。

4. 分红折现模型
   - 适合分红稳定、成熟期、现金回报明确的公司。
   - 输入：分红、分红率、分红增长率、权益资本成本、总股本。
   - MVP 可先保留 schema 和方法适配判断，第二轮实现完整计算。

5. 资产价值模型
   - 适合资产重、金融、困境反转或清算视角。
   - 输入：现金、有息负债、总资产、总负债、应收、存货、商誉、股东权益。
   - MVP 可先做资产负债安全检查和 `needs_input/skipped`，第二轮实现折扣清算口径。

MVP 定义：

- MVP 是“最小可用版本”，不是最终完整版。
- 010 MVP 的目标是先跑通一条可信闭环：读取最新 memo 和财务证据包，构建无价格污染快照，派生估值输入，生成可编辑三档参数，用 DCF 和所有者盈余计算总股权价值与每股内在价值，保存草稿，锁定版本，并为 011 提供前置估值 run。
- MVP 不追求覆盖所有行业和所有估值方法；剩余收益、分红折现、资产价值先进入方法框架和适配提示，后续逐步补完整计算。

折现率和永续增长率的处理：

- 模型可以辅助判断“建议区间”和解释原因，但不应单独决定最终参数。
- 服务层应提供规则边界和默认锚：公司质量、现金流稳定性、杠杆水平、周期性、财务数据完整度、009 的风险和反方证据会影响折现率区间。
- 永续增长率必须有保守上限，不能因为模型乐观叙述而放宽；高确定性消费类公司也只能在合理低增长区间内调整。
- 前端展示模型建议值、规则允许区间、来源说明和置信度，用户可以修改保守/中性/乐观三档参数。
- 保存 run 时同时记录 `model_suggested_assumptions`、`user_adjusted_assumptions` 和最终用于计算的 `assumptions`，便于复盘。

多模型输出口径：

## 2026-08-15 分析师信号到估值参数的明确映射与公式

目标：把 008 每位分析师的 `rule_checks[].status`、009 `valuation_signal_pack.analyst_signals[]` 转成“待用户确认”的估值参数建议。该层只生成参数建议，不直接计算估值数字；用户确认后才写入 010 `assumptions` 并由服务层公式计算。

### 1. 基础状态分值

008 标准状态先转成数值：

```text
pass    = +1.00
warn    = -0.35
fail    = -1.00
unknown =  0.00
```

`unknown` 不做正向或负向方向判断，但会增加不确定性惩罚：

```text
unknown_penalty = min(0.20, unknown_count / total_rule_count * 0.20)
```

每位分析师权重：

```text
analyst_weight_i = normalize(
  clamp(profile_fit_score_i, 0.20, 1.00)
  * clamp(data_confidence_i, 0.20, 1.00)
)
```

其中 `profile_fit_score` 表示该分析框架对公司的适配度，`data_confidence` 表示该分析师视角的证据底稿质量。

### 2. 信号字段分值

009 `valuation_signal_pack.analyst_signals[]` 的信号字段统一转成：

```text
positive = +1.00
neutral  =  0.00
negative = -1.00
unknown  =  0.00
```

若同时有 `rule_checks` 和信号字段，优先使用服务层从 `rule_checks` 归纳出的维度分；模型生成的信号字段作为补充，不得覆盖明确的 `fail` 风险。

### 3. 维度到估值参数的映射

各维度影响参数如下：

| 分析师信号维度 | 主要影响参数 | 正向影响 | 负向影响 |
| --- | --- | --- | --- |
| `business_quality_signal` | `discount_rate`, `scenario_spread`, method weight | 降低折现率、收窄情景区间、提高 DCF/所有者盈余权重 | 提高折现率、扩大情景区间 |
| `moat_durability_signal` | `terminal_growth_rate`, `discount_rate`, `scenario_spread` | 在硬上限内提高终值质量、降低折现率 | 降低永续增长率、提高折现率 |
| `growth_runway_signal` | `cash_flow_growth_rate`, `owner_earnings_growth_rate` | 提高显性期增长率 | 降低显性期增长率 |
| `pricing_power_signal` | `cash_flow_growth_rate`, `terminal_growth_rate` | 支持更稳的现金流增长和终值 | 降低增长和终值质量 |
| `capital_intensity_signal` | `owner_earnings_growth_rate`, `cash_flow_growth_rate`, method weight | 低资本消耗提高所有者盈余质量 | 高资本开支压低所有者盈余增长、降低 DCF 权重 |
| `cash_flow_reliability_signal` | DCF weight, `discount_rate`, `scenario_spread` | 提高 DCF/所有者盈余权重、降低折现率 | 降低现金流模型权重、扩大情景区间 |
| `balance_sheet_risk_signal` | `discount_rate`, asset/debt risk | 资产负债安全降低折现率 | 杠杆或偿债风险提高折现率 |
| `management_capital_allocation_signal` | `owner_earnings_growth_rate`, method weight | 提高所有者盈余质量、提高 owner earnings 权重 | 降低所有者盈余增长、提高折现率 |
| `cyclicality_signal` | `discount_rate`, `scenario_spread`, method weight | 周期弱可降低情景宽度 | 周期强则提高折现率、扩大区间 |
| `permanent_loss_risk_signal` | `discount_rate`, lock gate, confidence | 风险低可降低风险溢价 | 风险高则提高折现率、降低置信度，严重时阻止锁定 |

### 4. 聚合维度分

对每个维度 `d`：

```text
dimension_score_d =
  sum(analyst_weight_i * signal_score_i,d)
  / sum(analyst_weight_i with known signal_d)
```

若某维度大部分为 `unknown`：

```text
dimension_confidence_d =
  1 - min(0.35, unknown_ratio_d * 0.35)
```

分歧度：

```text
dimension_disagreement_d =
  weighted_std(signal_score_i,d)
```

如果 `dimension_disagreement_d > 0.65`，不强行提高估值，只扩大情景区间并降低置信度。

## 2026-08-16 估值假设队列定位与模型初始基准比例

说明：本节记录的两模型 `55%/45%` 基准已被后续“五模型基准权重与缺失重分配”覆盖，当前实现以文件末尾的 `35%/35%/10%/10%/10%` 为准。

队列中描述的底层事实仍可能通过其他结构化通道影响估值：

- 利润持续性：实际财务趋势中的 FCF、净利润、收入 CAGR 决定分析师影响前的基础增长率。

```text

```

理由：所有者盈余更直接关注企业在维持经营和必要再投资后可归属于所有者的现金能力，作为主要模型；DCF 保留较高比例用于现金流折现交叉验证，但降低其长期增长率和终值假设对综合结果的主导程度。
